# 콜비 — 제품 개요

## 프로젝트 이름

콜비(Kolbi, 구 CallMate). 콜비라는 이름은 이 `.moai/project/` 문서에서만 쓴다. `README.md`(제목 `# CallMate`), `docs/`, 코드, 패키지 이름·경로는 여전히 CallMate / `callmate`(`callmate`, `callmate-server` 등)를 쓰며, 이를 바꾸는 일은 아직 하지 않은 별도 작업이다.

## 설명

콜비는 고객을 대신해 기업 고객센터를 상대하고 맡긴 업무를 끝까지 마무리하는 개인 비서 에이전트를 지향한다(목표는 아래 「목표 방향」 참고). 현재 구현은 한국 시장을 대상으로 한 AI 전화 비서로, 사용자가 맡긴 전화 용건을 AI가 대신 처리한다. 통화 전에 계획을 세워 사용자의 승인을 받고, 통화 중 결제·계약처럼 중요한 결정이 필요하면 사용자에게 먼저 묻고, 통화가 끝나면 결과를 요약한다.

구성은 Flutter 앱(`app/`)과 Fastify/TypeScript 서버(`server/`) 두 부분이다. 「현재 구현」에 해당하는 절은 코드로 확인된 이 두 부분만 다루며, 목표 방향은 별도 절에 분리해 적는다.

## 대상 사용자

- 식당 예약, 영업시간 문의처럼 반복적이고 번거로운 전화를 직접 걸고 싶지 않은 한국어 사용자
- 요금 할인 요청, 해지·환불 요청처럼 협상이 필요하지만 최종 결정은 직접 내리고 싶은 사용자

현재는 개발 단계 제품이며(프로젝트 인터뷰에서 소유자는 1인 개발자가 운영한다고 밝혔다. 저장소로는 확인할 수 없다), 계정 시스템 없이 서버 하나에 `API_TOKEN` 하나로 접근을 제한한다.

## 현재 구현(코드로 확인됨)

### 핵심 기능

| 기능 | 설명 |
|---|---|
| 용건 위임 | 식당 예약, 영업시간 문의, 요금 할인 요청, 해지·환불 요청 등 |
| 통화 계획 검토 | AI가 세운 통화 계획을 사용자가 확인하고 승인한 뒤에만 발신 |
| 실시간 대화록 | 통화 중 대화 내용을 WebSocket(`/v1/stream`)으로 앱에 실시간 표시 |
| 통화 중 승인 | AI가 `request_user_approval` 도구로 결정을 요청하면 사용자가 승인·거절하고 선택적으로 코멘트(최대 500자)를 남김. 기본 응답 제한 시간은 90초(`APPROVAL_TIMEOUT_SEC`) |
| 결과 요약 | 통화 종료 후 결과(`CallOutcome`: 결과, 요약, 핵심 사실, 후속 조치) 제공 |
| 언어 | 작업 언어는 `ko`, `en` 두 가지(`server/src/domain/types.ts`의 `Language`) |

### 사용 시나리오

1. 사용자가 앱의 새 통화 화면(`/calls/new`)에서 상대 번호와 용건을 입력한다.
2. 앱이 `POST /v1/tasks`를 호출하면 서버가 작업을 만들고 통화 계획을 세운다(`planning`).
3. 계획이 준비되면 `awaiting_approval` 상태가 되고, 사용자가 계획을 검토해 승인한다(`POST /v1/tasks/:id/approve-plan`).
4. 서버가 발신하며 상태가 `dialing` → `ringing` → `in_progress`로 바뀐다. 앱은 대화록을 실시간으로 받는다.
5. 중요한 결정이 필요하면 앱에 승인 카드가 뜨고, 사용자가 응답한다(`POST /v1/tasks/:id/approvals/:approvalId`).
6. 통화가 끝나면 `summarizing`을 거쳐 `completed`가 되고 결과 요약이 표시된다. 실패하거나 사용자가 취소하면 `failed` 또는 `canceled`로 끝난다.

### 통화 생명주기

상태 정의: `server/src/domain/types.ts`의 `TaskStatus`. 상태 전이 규칙: `server/src/domain/stateMachine.ts`.

| 상태 | 의미 | 분류 |
|---|---|---|
| `planning` | 통화 계획 작성 중 | 준비 |
| `awaiting_approval` | 사용자의 계획 승인 대기 | 준비 |
| `dialing` | 발신 중 | 통화 중(`ACTIVE_CALL_STATUSES`) |
| `ringing` | 상대방 호출 중 | 통화 중 |
| `in_progress` | 통화 진행 중 | 통화 중 |
| `summarizing` | 통화 결과 요약 중 | 마무리 |
| `completed` | 완료 | 종료(`TERMINAL_STATUSES`) |
| `failed` | 실패 | 종료 |
| `canceled` | 취소 | 종료 |

### 현재 한계

- 푸시 알림이 없다. 통화 중 승인 요청은 앱이 열려 있고 WebSocket에 연결된 동안에만 받을 수 있다.
- 데이터는 단일 JSON 파일(`DATA_FILE`, 기본값 `data/tasks.json`)에 저장되며 데이터베이스를 쓰지 않는다.
- 사용자 계정이 없고, 서버 전체가 하나의 Bearer 토큰(`API_TOKEN`)을 공유한다.
- 기본 제공자는 시뮬레이션이다. KAT Cloud와 OpenAI Realtime을 쓰는 실제 통화 경로는 환경 설정에 의존하며, 실운영에서 검증된 경로로 보지 않는다.
- KAT Cloud는 한국 IP에서만 접근할 수 있어 `PUBLIC_BASE_URL`에 한국에서 접근 가능한 HTTPS 터널이 필요하다.
- 긴급·특수번호(112, 119, 113, 114, 117, 118, 122, 125, 182)는 발신이 차단된다.
- 동시 통화 2건, 하루 30건, 통화당 600초가 기본 상한이다.

## 목표 방향 (미구현, 소유자 진술 기준)

아래 내용은 소유자가 밝힌 방향이다. 「배포 형태」 중 독립 앱은 이미 `app/`(Flutter)으로 구현되어 있고, 그 밖의 항목은 이 저장소에 구현되어 있지 않다.

| 항목 | 소유자 진술 |
|---|---|
| 목적 | 단순히 전화를 거는 데 그치지 않고, 고객을 대신해 기업 고객센터와의 업무를 처음부터 끝까지 완결한다(Pickle과 같은 개인 비서 에이전트) |
| 역할 | 허브 플랫폼의 아웃바운드 측 에이전트. 허브가 다른 프로젝트에서 만드는 기업 인바운드 에이전트와 콜비를 연결하고, 인증·보안·라우팅을 맡는다 |
| 배포 형태 | 독립 앱(구현됨, `app/`)과 함께, 다른 앱이 통합해 쓸 수 있는 애드온·SDK로 제공(애드온·SDK는 미구현) |
| 허브 인증·라우팅 | 표준 프로토콜 A2A, MCP, OAuth, JWT, Ory Hydra 사용 |

- 허브 플랫폼과 기업 인바운드 에이전트는 이 저장소에 없다.
- `docs/04_SDK_ADDON_PLATFORM_ARCHITECTURE.md`가 SDK·애드온 플랫폼을 제안하고 있으나 구현되지 않은 제안이다.
- A2A, MCP, OAuth, JWT, Ory Hydra는 `server/package.json`, `app/pubspec.yaml`, `server/src`, `app/lib` 어디에도 나오지 않는다(의존성·코드에 없음).
- 열린 질문(미결정): 기업과의 연결을 전화 음성으로 할지, 허브의 에이전트 간 채널로 할지, 둘 다 쓸지는 정해지지 않았다.
