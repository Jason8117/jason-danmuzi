# CallMate 제품 고도화 로드맵

> 목표: **전화 대행 MVP**를 넘어, 일상 업무를 대신 처리하는 **개인 AI 비서**로 확장한다.  
> 작성 기준: 현재 구현(KAT Cloud 발신 + OpenAI Realtime + 통화 중 승인)과 Pickle·익시오·HeyRobyn 등 벤치마크.

---

## 0. 한 줄 요약

| 지금 | 다음 | 장기 |
| --- | --- | --- |
| AI가 대신 전화하고, 중요 결정은 예/아니오로 승인 | 승인에 **코멘트·추가 정보**를 실어 보내고, 자주 쓰는 상대·템플릿·푸시·연락처를 붙인다 | 채팅·음성으로 일을 맡기고, **커넥터**(캘린더·메일·예약·결제)와 **수신 대행**까지 하는 개인 비서 |

## 1. 현재 완성도 (MVP 점검)

### 1.1 이미 되는 것

- 전화 맡기기 → 계획 검토 → KAT Cloud(070) 실제 발신
- 실시간 자막, 통화 끊기, 결과 요약
- 통화 중 승인(예/아니오) + 제한 시간
- 키 없을 때 시뮬레이터로 전체 UX 체험

### 1.2 서비스 “완성도”를 위해 아직 약한 것

| 영역 | 갭 | 왜 중요한가 |
| --- | --- | --- |
| **승인 UX** | 승인/거절만 가능, 텍스트 코멘트 없음 | “예약금 3만은 OK인데 카드는 안 된다”처럼 조건부 지시가 불가 |
| **신뢰·알림** | 푸시 없음, 백그라운드 시 승인 놓침 | 실제 통화 중 승인이 제품의 핵심인데 화면을 보고 있어야 함 |
| **입력 편의** | 번호·목적을 매번 타이핑 | 연락처·최근 상대·음성 입력이 없으면 반복 사용이 불편 |
| **기억** | 자주 가는 식당/고객센터 저장 없음 | Pickle류는 “다시 그 일”을 한 번에 시킴 |
| **후속 행동** | 요약만 보여 줌 | 캘린더 등록, 메모, 재통화, 공유가 없으면 일이 앱 밖에서 끊김 |
| **계정·동기화** | 로컬 설정 + 단일 서버 | 기기 바꾸면 설정·기록이 사라짐 |
| **수신** | 발신만 | “대신 받기”는 한국 사용자 기대치가 높음(익시오 등) |
| **웹/앱 연동** | 없음 | 전화로만 되는 일 + 웹으로 되는 일을 한 비서에 묶는 것이 차별점 |
| **법·신뢰** | AI 고지·약관 UI는 기초 수준 | 실서비스 출시 전 필수 |

## 2. 즉시 개선: 승인 시 추가 정보·코멘트

### 2.1 사용자 니즈

통화 중 승인 화면에서 지금처럼 질문만 보고 예/아니오를 고르는 대신,

- **승인 + 코멘트**: “3만 원까지는 괜찮아요. 식권은 쓰지 마세요.”
- **거절 + 이유**: “오늘은 안 됩니다. 내일 저녁으로 물어봐 주세요.”
- **추가 정보 제공**: 성함 철자, 인원, 알레르기, 회원번호 등 AI가 다시 말해야 할 내용

### 2.2 제품 동작 (제안)

```text
[승인 카드]
  질문: "예약금 3만 원을 결제해도 될까요?"
  ┌─────────────────────────────────────┐
  │ 추가 안내 (선택)                      │
  │ 예: 카드는 안 되고 계좌이체만…         │
  └─────────────────────────────────────┘
  [거절]              [이대로 승인]
```

1. 사용자가 승인/거절 + (선택) 코멘트를 보냄  
2. 서버가 AI(Realtime 도구 결과)에 전달:

```json
{
  "approved": true,
  "comment": "3만 원까지 OK. 카드 결제는 거절하고 계좌이체만 가능하다고 전하세요."
}
```

3. AI는 상대에게 그 조건을 반영해 이어감 (지시문에 “사용자 코멘트를 그대로 따르라” 명시)

### 2.3 구현 범위 (작음 → 바로 착수 가능)

| 레이어 | 변경 |
| --- | --- |
| API | `POST .../approvals/:id` body에 `comment?: string` (길이 제한 예: 500자) |
| 도메인 | `ApprovalRequest`에 `userComment?`, 결정 시 저장 |
| CallSession | `requestApproval` 반환을 `boolean` → `{ approved, comment? }` |
| Realtime | tool 결과에 `instruction` + `user_comment` 포함 |
| 앱 | `ApprovalCard`에 텍스트 필드 + 승인/거절 시 전송 |
| 기록 | 결과 화면·통화 기록에 “내가 남긴 안내” 표시 |

### 2.4 UX 규칙

- 코멘트는 **선택**. 비우면 지금과 동일  
- 타이머가 촉박할 때 입력 중이어도 **만료 = 거절**(안전 기본값 유지)  
- 민감정보(카드번호·비밀번호·주민번호)는 입력창 helper로 금지 안내 + 서버/프롬프트에서 재강조  
- 거절 시에도 코멘트를 허용해 “대안 제안”을 AI가 말할 수 있게

## 3. 벤치마크 요약

### 3.1 Pickle (개인 AI 에이전트)

강점 (CallMate가 배울 점)

| 기능 | 시사점 |
| --- | --- |
| 채팅·음성·전화로 일 맡기기 | 전화 전용 UI만으로는 비서처럼 안 느껴짐 → **대화형 진입점** 필요 |
| 전화 + 웹 브라우저 작업 | 전화로만 되는 일과 웹으로 되는 일을 한 작업으로 묶음 |
| **커넥터** (Gmail, Calendar, Amazon, OpenTable 등) | “연결한 앱”이 많을수록 가치 상승 |
| 결제·예약 전 **승인** | CallMate와 동일한 철학 — 여기에 **코멘트형 승인**을 얹으면 차별화 |
| 이메일·캘린더 기반 **할 일 제안** | 수동 입력 줄이기 |
| 실시간으로 통화·브라우저 감시 | 투명성 = 신뢰 |
| 메모리(선호·과거 맥락) | 반복 통화 품질↑ |

약점·주의

- 자동화·웹 스크래핑은 약관·법적 리스크  
- 한국 전화망·070 발신·국내 서비스 연동이 핵심 기회 (Pickle의 미국/글로벌 중심과 반대)

### 3.2 LG U+ 익시오 / SKT 에이닷

| 기능 | CallMate 관점 |
| --- | --- |
| AI 대신 받기, 보이스피싱 탐지 | **수신** 시나리오 수요 확인 |
| 통화 요약·할 일 제안 | 통화 후 **액션 카드**(캘린더/문자/재통화) |
| 통신사 락인 | CallMate는 **통신사 무관** 발신 대행으로 포지셔닝 가능 |

### 3.3 HeyRobyn / Simple AI / Google Duplex

- Duplex: 단순 예약에 강함, 복잡한 CS·요금 협상은 약함 → CallMate는 **복잡 통화**에 집중  
- HeyRobyn류: 대기열(hold) 버티기, 빌링 분쟁 → “기다리는 일” UX·상태 표시가 중요

### 3.4 CallMate만의 포지션 (제안)

```text
「한국에서, 전화로만 되는 일을 AI가 대신 하고,
  중요한 순간에는 내가 한 줄로 조건을 달아 승인하는 개인 비서」
```

- 국내 070 발신(KAT) + 한국어 실시간 통화  
- 승인에 **코멘트**를 실어 “조건부 위임”  
- 이후 커넥터·수신·음성 입력으로 비서 영역 확대

## 4. 개인 비서화를 위한 기능 맵

### 4.1 P0 — 통화 제품의 완성 (4~8주 목표)

| 우선 | 기능 | 설명 |
| --- | --- | --- |
| P0 | **승인 코멘트** | §2 |
| P0 | **푸시 알림** | 승인 요청·통화 종료·실패 시 FCM/APNs |
| P0 | **자주 쓰는 상대·템플릿** | 식당/은행/통신사 저장, “저번에 그 예약” 재실행 |
| P0 | **연락처 선택** | 기기 주소록에서 번호 고르기 (`contacts_service`) |
| P0 | **음성으로 부탁 입력** | STT로 goal/context 작성 (통화 대행과 별개 입력 UX) |
| P0 | **통화 후 액션** | 요약 → 캘린더 초안, 메모 복사, 재통화, 공유 |
| P0 | **신뢰 UI** | AI 고지 문구, 녹음/자막 안내, 권한 설명 |

### 4.2 P1 — 비서의 “손발” (커넥터·자동화)

| 우선 | 기능 | 설명 |
| --- | --- | --- |
| P1 | **커넥터 모듈 + 설정 UI** | OAuth/API 키로 외부 서비스 연결, 권한 on/off |
| P1 | **1차 커넥터 후보** | Google Calendar, Gmail(또는 네이버/다음 메일), 카카오톡(정책 가능 시), OpenAI 외 STT |
| P1 | **장소·업체 검색** | 네이버/카카오 로컬 검색 → 전화 대상 자동 채움 |
| P1 | **예약 통화** | “내일 10시에 병원 확인해 줘” |
| P1 | **ARS/DTMF** | 고객센터 메뉴 탐색 |
| P1 | **계정·클라우드 동기화** | 로그인, 기기 간 작업·커넥터 동기화 |

**커넥터 설계 원칙**

```text
app/features/connectors/
  domain/          Connector, Capability, AuthKind
  data/            OAuth / API key adapters
  presentation/    설정 > 연결된 앱 목록, 권한 토글

server/connectors/
  registry.ts      등록된 커넥터
  googleCalendar/
  ...
```

- 커넥터는 **읽기 / 쓰기 / 결제** 권한을 분리  
- 쓰기·결제는 항상 사용자 승인(코멘트 가능)  
- “API가 있는 웹·앱”은 공식 API 우선, 없으면 **딥링크·공유 시트**로 사용자 개입형 연결부터

### 4.3 P2 — 멀티모달 개인 비서

| 우선 | 기능 | 설명 |
| --- | --- | --- |
| P2 | **홈을 채팅으로** | “피자 예약해 줘” → 계획 카드 → 전화/웹 분기 |
| P2 | **상시 음성 비서** | 앱에 말해 일 맡기기 (Pickle의 voice/message) |
| P2 | **카메라** | 영수증·예약 문자 화면·명함 OCR → 통화/저장 초안 (권한 명시, 얼굴 식별 목적 금지) |
| P2 | **수신 대행** | KAT 스트림 인바운드 + “지금 대신 받기” (익시오형) |
| P2 | **메모리** | 선호 식당, 알레르기, 회원번호 — 사용자가 보고 지울 수 있게 |
| P2 | **친구·공유 작업** | 일정 조율(후순위, 프라이버시 큼) |

### 4.4 권한·프라이버시 (카메라·연락처·마이크)

| 권한 | 사용처 | 원칙 |
| --- | --- | --- |
| 마이크 | 부탁 음성 입력, (선택) 통화 중 사용자 끼어들기 | 목적별 런타임 권한, 상시 녹음 금지 |
| 연락처 | 수신자 선택 | 서버로 전체 주소록 업로드 금지 — 선택 항목만 전송 |
| 카메라 | OCR·서류 스냅 | 로컬 처리 우선, 업로드 시 명시 동의 |
| 알림 | 승인·결과 | 채널 분리(긴급 승인 / 일반) |
| 캘린더·메일 | 커넥터 | OAuth 최소 스코프, 언제든 해제 |

| 일정 잡기 | 비서 체감 | Calendar 커넥터 |

## 6. 단계별 로드맵

### Phase A — “믿기고 쓰기 편한 전화 비서” (단기)

1. 승인 코멘트  
2. 푸시 알림  
3. 자주 쓰는 상대 + 템플릿  
4. 연락처 피커 + 음성으로 부탁 쓰기  
5. 통화 후 액션(복사/재통화/캘린더 초안)

**성공 지표:** 주당 재사용률, 승인 응답률(만료↓), 통화 완료율

### Phase B — “연결된 비서” (중기)

1. 커넥터 프레임워크 + 설정 UI  
2. Google Calendar / 국내 지도·업체 검색  
3. 예약 통화, ARS  
4. 계정·동기화

**성공 지표:** 커넥터 연결률, 전화 없는 후속 작업 완료 수

### Phase C — “개인 AI 에이전트” (장기)

1. 채팅 홈 + 상시 음성  
2. 카메라 OCR  
3. 수신 대행  
4. 메모리·제안(“이번 주 끊을 구독 후보”)  
5. (신중히) 웹 에이전트·결제 승인 플로우

**성공 지표:** 일일 활성, 제안 수락률, 전화 외 작업 비중

## 7. 기술 메모 (구현 시 참고)

### 7.1 승인 코멘트 데이터 흐름

```text
앱 ApprovalCard
  → POST /v1/tasks/:id/approvals/:approvalId
       { decision: "approve"|"reject", comment?: string }
  → CallService.respondToApproval(..., comment)
  → requestApproval Promise resolve({ approved, comment })
  → Realtime tool output
       { approved, user_comment, instruction }
```

### 7.2 커넥터 인터페이스 (초안)

```ts
interface Connector {
  id: string;                 // "google_calendar"
  name: string;
  capabilities: Array<"read_events" | "write_events" | "search_places" | ...>;
  connect(auth): Promise<void>;
  disconnect(): Promise<void>;
  // 실제 호출은 서버에서만 — 앱은 토큰을 서버에 위임
}
```

### 7.3 기존 아키텍처와의 관계

- 전화 경로: 계속 `CallProvider`(KAT) + Realtime  
- 비전화 작업: 새 `AgentTask` / `Connector` 레이어  
- 승인은 **전화·웹·결제 공통 패턴**으로 일반화 (`ApprovalGate`)

자세한 통화 내부 설계는 [ARCHITECTURE.md](./ARCHITECTURE.md)를 본다.
