### 1.1 순서를 이렇게 둔 이유

| 결정 | 이유 |
|---|---|
| 디자인 시스템을 셸 앞에(2026-11-26) | 토큰·글꼴·칩 교체는 기존 테스트가 깨질 위험과 대비 위험이 가장 큰 부분이다. 셸과 섞으면 테스트가 깨졌을 때 원인을 가리기 어렵고 셸 SPEC이 Tier 범위를 크게 넘는다(plan-audit 1차 권고). 화면 글자·배치를 바꾸지 않으므로 셸보다 먼저 끝낼 수 있다 |
| 패키지 분리를 맨 앞에 | 이후 모든 SPEC이 새 파일을 어느 패키지에 둘지 정해야 한다. 분리를 늦추면 그 사이에 만든 화면을 다시 옮긴다. 동작 불변이라 위험이 가장 작고, 테스트 80개가 그대로 회귀 검사가 된다 |
| 비서를 장소보다 먼저(2026-11-26) | 부탁 흐름의 입구가 홈 입력칸에서 AI 비서 화면으로 바뀌었다(06 DR-4). 장소 선택(SCR-H02)은 비서 화면 다음에 열리므로, 입구가 먼저 있어야 장소 SPEC의 진입과 뒤로 가기 규칙이 정해진다 |
| 셸을 장소보다 먼저 | 장소 후보(SCR-H02)는 홈 부탁 흐름 안에 쌓이는 카드다(04 §6.3). 홈과 탭 구조가 먼저 있어야 자리가 정해진다. 작업 종류 등록부도 셸에서 만들어야 반복(`reminder`)이 꽂힌다 |
| 장소를 반복보다 먼저 | Phase 1의 중심 흐름(한 줄 부탁 → 장소 → 계획 → 통화, 03 §6 흐름 1)을 먼저 끝낸다. 반복 알림은 독립 기능이다 |
| 허브를 SDK보다 먼저 | 서버 인증 경계(`Principal`)를 허브 SPEC에서 만들고, SDK의 공개 API가 그 경계 위에 선다. 순서를 바꾸면 SDK가 임시 인증을 만들고 허브 SPEC이 다시 고친다 |
| 허브를 장소 다음에 | 경로 조회(`lookupRoute`)의 입력이 장소 id·이름·번호다. 장소 모델이 있어야 조회 입력이 안정된다 |
| 앞의 권장 순서를 바꾸지 않음 | 요청에서 권장한 순서(MODULE → SHELL → PLACE → ROUTINE → HUB → SDK)가 위 의존 관계와 맞아 그대로 두고, 2026-11-26에 SHELL과 PLACE 사이에 ASSIST만 끼웠다 |

## 2. 차수별 계획

### 2.1 1차 — SPEC-MODULE-001 워크스페이스와 패키지 분리 (Priority High)

- **범위**: 루트 워크스페이스, `packages/kolbi_core`(순수 Dart), `packages/kolbi_ui`(Flutter), 옮길 파일 목록대로 이동, 옛 경로는 다시 내보내기(re-export) 파일로 남김, 의존 규칙 테스트.
- **들어가는 조건**: 앱 테스트 80개 통과(2026-11-26 `flutter test` "+80: All tests passed!"), `flutter analyze` 기준선 기록, 서버 `npm test`·`npm run typecheck` 기준선 기록.
- **나오는 조건**: 테스트 80개가 **수정 없이** 통과, 새 패키지 테스트 통과, 의존 규칙 테스트 통과, `flutter analyze` 새 문제 없음, `server/`와 `/v1` 변경 없음(`git diff --stat -- server/` 비어 있음).
- **실제/가짜**: 해당 없음(구조만).
- **검증**: `flutter test`(app), `dart test`(kolbi_core), `flutter test`(kolbi_ui), `flutter analyze`, import 규칙 테스트. 서식은 옮기거나 고친 파일에만 `dart format`을 돌린다(저장소 전체 서식 실행 금지 — 프로젝트 규칙).

### 2.2 2차 — SPEC-DESIGN-001 토큰·글꼴·상태 칩, SPEC-SHELL-001 5칸 셸·작업 종류 등록부 (Priority High)

- **범위(2026-11-26 개정)**: 오늘·업무·기록·내 정보 4갈래 셸과 가운데 비서 버튼(CMP-01 개정, CMP-36. 버튼은 이 SPEC에서는 기존 부탁 입력 화면을 연다), Midnight Indigo 토큰 교체와 Pretendard 글꼴(06 §3), 상태 칩 5종(CMP-28 개정), 경로 이름과 셸 라우터, `TaskKind` 서술자·표시자·등록부와 `call` 등록, 업무 묶음(승인 요청/진행 중/반복)과 배지, 기록 목록(SCR-R01), 업무 실행 단계 화면(SCR-T02, `taskSteps`, CMP-34), 오늘 화면(작업 기반 브리핑·바로가기·확인이 필요해요·진행 중, 04 §17.2), 내 정보 탭(04 §17.8), 기능 간 import 위반 0.
- **들어가는 조건**: SPEC-MODULE-001 `completed`.
- **나오는 조건**: 기존 통화 흐름(계획 확인 → 업무 실행 → 통화 → 승인 → 결과)이 새 셸 안에서 그대로 동작, 인수 기준에 이름을 적은 테스트 외 기존 테스트 수정 없이 통과, 새 위젯 테스트 통과, 바뀐 토큰 값으로 대비 테스트 통과, 의존 규칙 허용 목록이 비어 있음.
- **실제/가짜**: `/v1` 그대로. 반복 묶음은 빈 안내 한 줄(실제 반복은 4차).
- **검증**: `flutter test`, `flutter analyze`, 접근성 지침 검사를 오늘·업무·기록·내 정보·업무 실행으로 확대(밝은·어두운 모드, 글자 배율 2.0), `taskSteps` 단위 테스트, 앱 빌드 크기 비교(Pretendard, 가정 A-6), 서버 변경 없음.

### 2.3 3차 — SPEC-ASSIST-001 AI 비서와 받아쓰기 (Priority High, 2026-11-26 추가)

- **범위**: `features/assistant`(SCR-A01, 04 §17.4), `kolbi_ui`의 `KolbiOrb` 상태 4종 움직임(CMP-35, 움직임 줄이기 대응)과 몰입형 다크 테마, 받아쓰기(F-REQ-02, 기기 음성 인식, OD-K8), 마이크 권한 사전 안내(CMP-23), 가운데 비서 버튼을 AI 비서 모달로 연결(F-ASST-02), 받아쓴 문장을 기존 `/v1/intake`로 보내 계획 확인으로 이어 줌, 통화 중 화면(SCR-T08)을 기존 통화 상세의 대화 기록·승인·끊기로 만듦(04 §17.6).
- **들어가는 조건**: SPEC-SHELL-001 `completed`. 음성 인식 패키지 선정(가정 A-7).
- **나오는 조건**: 음성은 서버로 보내지 않음(글만), 마이크가 켜진 동안 "듣고 있어요" 상시 표시, 권한 거부 시 글로 입력으로 계속 가능, 몰입형 다크 화면 대비 4.5:1, 기존 통화 흐름 테스트 통과.
- **실제/가짜**: 기기 음성 인식은 실제, 위젯 테스트는 가짜 인식기.
- **검증**: `flutter test`(가짜 인식기로 듣는 중 → 처리 중 → 계획 확인 이동), 접근성 지침 검사(다크), 서버 변경 없음.

### 2.4 4차 — SPEC-PLACE-001 장소 찾기 (Priority High)

- **범위**: 서버 `places` 모듈(`PlaceSearchProvider` 포트, 시뮬레이션 제공자, 카카오 로컬 어댑터), `POST /v1/places/search`(더하기만), 앱 `features/places`(SCR-H02 장소 후보 CMP-05, SCR-H03 장소 상세 시트 CMP-06), 후보 선택 → 계획 카드(번호·출처 채움), 계획 카드 다이어트 일부(펼침 규칙 D-4: 확인할 칸만 펼침), "최근 통화한 곳" → "최근 장소".
- **들어가는 조건**: SPEC-ASSIST-001 `completed`. OD-5 기본값 확인(검색 결과 비저장).
- **나오는 조건**: 검색 결과가 저장소·로그에 남지 않음을 테스트로 확인, 번호 없는 후보는 선택 불가, 발신 불가 번호는 이유와 함께 비활성, 키 없이 시뮬레이션으로 전 흐름 동작.
- **실제/가짜**: 카카오 로컬은 키가 있을 때만(기본 시뮬레이션). 카카오 요청·응답 필드는 착수 시 공식 문서로 확인(검증 필요).
- **검증**: 서버 `npm test`(포트 계약 테스트, 저장 금지 테스트), `npm run typecheck`, `architecture.test.ts` 규칙 추가, 앱 위젯 테스트.

### 2.5 5차 — SPEC-ROUTINE-001 반복 알림과 바로 열기 (Priority Medium)

- **범위**: 서버 `routines` 모듈과 `/v1/routines`, 실시간 `routine.updated`, `kolbi_core`의 다음 실행 시각 계산(아시아/서울 기준, 순수 함수), 앱 `features/routines`(SCR-H06 반복 설정 시트 CMP-25, SCR-T07 반복 상세 CMP-24), 작업함 반복 묶음, 기기 로컬 알림 예약과 알림 누르면 딥링크·사이트 열기(F-ROUT-01·02), `reminder` 작업 종류 등록.
- **들어가는 조건**: SPEC-SHELL-001 `completed`(PLACE-001 다음에 run). 로컬 알림 패키지 선정(가정 A-4 확인).
- **나오는 조건**: 무인 실행 경로가 없음(알림은 열기만), 일시정지·삭제가 예약을 취소, 알림 문구에 민감 정보 없음(04 §13.3 잠금 화면 문구 검사 방식), 옛 앱이 `routine.updated`를 무시.
- **실제/가짜**: 기기 로컬 알림은 실제, 푸시는 없음. 위젯 테스트는 알림 예약기를 가짜로 바꿔 검사.
- **검증**: 다음 실행 시각 단위 테스트(월말·요일·서머타임 없는 시간대), 서버 테스트, 앱 위젯 테스트.

### 2.6 6차 — SPEC-HUB-001 허브·A2A 포트와 인증 경계 (Priority Medium)

- **범위**: 서버 `auth`(`Authenticator`, `Principal`, `StaticTokenAuthenticator`), `channels`(`TaskChannel`, `PhoneChannel`이 기존 경로를 감쌈, `ChannelRouter`), `hub`(`HubClient`, `A2AConnection`, `A2AChannel`, `FakeHub`, 가짜 인바운드 에이전트, 계약 테스트 모음, Agent Card 생성), A2A 상태 대응표 구현, 허브 토큰 포트(client credentials·위임 토큰)와 가짜 구현, 허브 콜백 JWT 검증 함수, 계획 카드에 실행 경로 표시(앱).
- **들어가는 조건**: SPEC-PLACE-001 `completed`. OD-K4·OD-K5 기본값 확인.
- **나오는 조건**: `HUB_ENABLED` 꺼짐(기본)에서 기존 서버 테스트 전부 수정 없이 통과, `PhoneChannel` 감싸기 후 `callService.test.ts` 그대로 통과, 계약 테스트 모음이 `FakeHub`에 대해 통과, 정적 토큰 인증 동작이 지금과 같음(401 조건 동일).
- **실제/가짜**: 허브·인바운드 에이전트·Hydra는 모두 가짜. 실제 허브 어댑터(`HttpHubClient`)는 허브 준비 뒤 별도 SPEC.
- **검증**: 서버 `npm test`, `typecheck`, `architecture.test.ts`에 `channels`·`hub`·`auth` 규칙 추가, 앱 위젯 테스트(실행 경로 표시).

### 2.7 7차 — SPEC-SDK-001 SDK 최소 범위 (Priority Medium)

- **범위**: `kolbi_core`의 `KolbiClient` 공개 API와 `AuthTokenProvider`(앱은 정적 구현 사용, 요청 헤더 불변), 버전 병합 함수 공유, `/platform/v1` 최소 경로(기능 플래그·sandbox), OpenAPI 명세와 계약 테스트, `kolbi_ui`의 `KolbiTaskFlow`·`KolbiApprovalCard`(승인 카드를 콜백 모양으로 추출하고 앱도 같은 위젯 사용), 테마 덮어쓰기, `examples/host_app`, 패키지 `CHANGELOG.md`.
- **들어가는 조건**: SPEC-HUB-001 `completed`(서버 인증 경계).
- **나오는 조건**: `/v1` 변경 없음, 앱 테스트 통과(승인 카드 추출 후에도), 예제 앱 위젯 테스트 통과, 공개 표면에 비밀·서버 주소 기본값 없음, 다른 principal의 작업 조회가 404(가짜 두 사용자로).
- **실제/가짜**: 시뮬레이터 서버와 가짜 BFF. 외부 파트너 노출 금지(Phase 0 이후).
- **검증**: `dart test`·`flutter test`(세 패키지와 예제), 서버 계약 테스트(명세 대조), 의존 규칙 테스트(예제가 `/src/`를 가져오지 않음).
