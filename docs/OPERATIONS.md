# 운영·배포 메모

서버(`server/`) 운영 시 지켜야 할 전제와 v0.2.0 변경(SPEC-STORE-001, SPEC-LIFECYCLE-001, SPEC-POLICY-001, SPEC-OUTCOME-001, SPEC-ARCH-001)에 따른 주의 사항을 정리한다. 이 저장소에는 Dockerfile, 호스팅 설정, 빌드·배포 CI가 없으므로(`.github/workflows/`에는 `label-sync.yml`뿐) 아래 내용은 특정 플랫폼이 아니라 서버 코드의 동작을 기준으로 한다.

## 실행 전제

- **단일 인스턴스.** 작업 저장소는 `DATA_FILE`(기본 `data/tasks.json`) 하나를 쓰는 JSON 파일이며 프로세스 간 잠금이 없다. 한 `DATA_FILE`은 한 프로세스만 쓰도록 하고, 같은 파일을 공유하는 다중 인스턴스나 수평 확장은 하지 않는다.
- 저장소 쓰기가 실패해도 요청 처리는 계속되며, 실패한 쓰기는 상한이 있는 간격으로 재시도한다. 종료 시 최종 flush 결과가 종료 코드에 반영된다(성공 0, 실패 1).

## 배포 시점과 종료 절차

- **진행 중인 통화가 없을 때만 배포한다.** SIGTERM(또는 SIGINT)을 받으면 서버는 다음 순서로 종료한다(`server/src/shutdown.ts`).
  1. 신규 작업을 막는다. 이 동안 들어온 작업 생성 요청은 HTTP 503 `shutting_down`을 받는다.
  2. 진행 중인 통화를 끊고, 해당 작업을 `failed`로 기록한다.
  3. HTTP 서버와 미디어 소켓을 닫는다.
  4. 저장소를 최종 flush하고 종료한다.
- 단계별 예산은 3 s + 1 s + 5 s, 합계 9 s다. **플랫폼의 종료 유예 시간(SIGTERM 후 강제 종료까지)은 최소 10 s로 설정한다.** 이보다 짧으면 통화 정리나 최종 저장이 끝나기 전에 프로세스가 강제 종료될 수 있다.
- 재기동 시 이전 프로세스가 남긴 통화(제공자 통화 ID가 저장된 작업)는 끊고 정리한다.

## 서버와 앱은 같은 릴리스로 배포

- 서버는 LLM이 검증하지 않은 휴리스틱 요약을 `result: "unverified"`, `source: "heuristic"`으로 기록한다(성공을 주장하지 않음).
- 이 값을 모르는 이전 버전 앱은 `unverified`를 `failed`로 표시한다. **서버와 앱을 같은 릴리스에 함께 배포한다.**
- 이미 저장된 작업은 예전 결과를 그대로 유지한다. 과거 작업을 다시 분류하지 않는다.

## KAT 통화 제한 시간

- KAT에 보내는 `timeLimit`은 `MAX_CALL_DURATION_SEC + 30`을 [10, 14400] 초 범위로 자른 값이다(`katTimeLimitSec`, `server/src/providers/kat/katProvider.ts`). 서버 자체 통화 시간 타이머가 KAT보다 먼저 통화를 끝내도록 30 s 여유를 둔 것이다.
- 이 30 s 여유는 `MAX_CALL_DURATION_SEC`가 14,370 s 이하일 때만 온전히 유지된다. 14,371~14,400 s에서는 여유가 30 s보다 줄고, 14,401 s 이상이면 KAT 상한(14,400 s)이 서버 타이머보다 먼저 통화를 끊는다.
- **동작 변경:** 이전에는 `timeLimit`이 900 s(15분)로 고정이었다. 이제 기본값 `MAX_CALL_DURATION_SEC=600` 기준 630 s가 된다. 15분 가까운 통화가 필요하면 `MAX_CALL_DURATION_SEC`를 명시적으로 올린다.

## 발신 번호 정책

- 긴급·특수번호(112, 119, 113, 114, 117, 118, 122, 125, 182) 발신은 HTTP 400 `blocked_number`로 거부한다. 검사는 서비스 계층(`CallService`)에서 작업 생성 시와 발신 직전 두 번 한다.

## 알려진 잔여 위험 (후속 SPEC 후보)

- **짧은 번호로 시작하는 긴 번호는 차단되지 않는다.** 예를 들어 `119-1234-5678`은 기존 정규화 규칙에 따라 `+11912345678`이 되어 차단 목록과 일치하지 않는다. 이번 변경 이전부터 있던 정규화 동작이며 별도 SPEC으로 다룰 후보다.
- **`+82`가 아닌 번호는 KAT에 숫자만 남긴 형태로 전달된다.** 국제 번호의 국가 코드 처리는 검증되지 않았다.
- KAT + OpenAI Realtime 실제 통화 경로는 자동 테스트로 검증하지 않는다(테스트는 모두 대역을 사용).
