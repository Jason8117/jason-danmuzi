## 2. 디자인 콘셉트

### 2.1 비서의 성격을 시각과 말투로 옮기는 방법

03 §2.1은 비서의 성격을 "해요체, 할 수 있는 일과 없는 일을 먼저 밝힘, 상대에게 정중함, 목적을 하나의 작업으로 받음"으로 정했다. 이를 다섯 가지 브랜드 키워드로 옮긴다.

| 키워드 | 뜻 | 시각으로 옮기는 방법 | 말투로 옮기는 방법 |
|---|---|---|---|
| **믿음직한** | 맡긴 일을 끝까지 챙긴다 | 단계 타임라인, 진행 중에도 홈·작업함·잠금 화면 어디서나 같은 단계 이름 | "끝나면 알려 드릴게요", "제가 확인해 볼게요" |
| **차분한** | 기다림을 불안하게 만들지 않는다 | 중립 표면이 기본, 움직임은 상태가 바뀔 때만 250 ms, 깜박임은 진행 점 하나 | 서두르게 하지 않는 문장. "상대방이 기다리고 있어요"까지만, "서두르세요"는 쓰지 않음 |
| **분명한** | 확인된 것과 아닌 것을 섞지 않는다 | "확인 못 함"은 중립 색·물음표 아이콘, 확정만 긍정 색. 숫자는 표 숫자(tabular) | "예약됐어요" / "예약 여부는 확인하지 못했어요"처럼 단정과 유보를 구분 |
| **정중한** | 사용자와 통화 상대 모두에게 예의를 지킨다 | 강요 문구·공포 조성 없음, 거절 버튼도 같은 크기 | 화면 문구와 통화 음성이 같은 사람처럼 들림(02 §6, 03 §2.1) |
| **선을 지키는** | 해도 되는 일과 안 되는 일의 경계를 보여 준다 | 손 넘기기 화면의 "기록하지 않아요" 표시, 하지 않는 일은 온보딩 첫 장에 | "여기서부터는 직접 해 주세요", "비밀번호는 받지 않아요" |

### 2.2 톤 앤 보이스 규칙

1. **해요체 한 가지.** 화면·알림·공유 문구·통화 음성 모두 해요체다(03 §2.1, EPIC D11). "~합니다", "~하십시오"는 쓰지 않는다. 버튼은 짧은 동사형("승인", "거절", "이대로 시작")을 쓴다.
2. **주어는 생략하고, 필요하면 "제가"·"콜비가".** 비서가 한 일은 "걸었어요", "확인했어요"처럼 행위로 말한다. "AI가 ~했습니다" 같은 3인칭 보고체는 고지 문구에서만 쓴다.
3. **구체적인 단계 이름.** "처리 중…", "로딩 중"을 쓰지 않는다. "전화 거는 중", "결과 정리 중"처럼 지금 하는 일을 쓴다(02 §1-5, 02 §4.1).
4. **이유를 한 줄 붙인다.** 멈추거나 요청할 때는 이유를 함께 쓴다(02 §3.10 Explain Why, 02 §5 P15).
5. **유보는 유보로.** 확인하지 못한 것은 "~인 것 같아요"로 흐리지 말고 "확인하지 못했어요"로 쓴다(03 F-RES-01, EPIC D5).
6. **강요·공포 금지.** 이탈 막기, 과장, 손해 강조 문구를 쓰지 않는다(02 §6 "강요하지 않는 문구").
7. **한 화면 한 메시지.** 제목 한 줄, 설명 최대 두 줄. 설명이 세 줄을 넘으면 화면을 나누거나 "자세히 >"로 접는다(02 §3.10 One Thing).
8. **숫자와 시간 표기.** 날짜는 "11월 28일(금)", 시각은 "오후 7시"(분이 있으면 "오후 7시 30분"), 금액은 "10,000원", 경과·남은 시간은 "1:24". 상대 시간("어제", "방금 전")은 목록에서만 쓴다.

### 4.5 아이콘

- 현재 코드는 `_outlined`와 `_rounded` 변형이 섞여 있다(`Icons.shield_outlined`, `Icons.phone_in_talk_rounded` 등). **둥근(rounded) 변형으로 통일**하고, 선택 상태(현재 탭, 켜진 토글의 앞 아이콘)만 채운 모양을 쓴다.
- 아이콘만 있는 버튼은 모두 툴팁과 접근성 라벨을 가진다(UX-001 REQ-012 유지).
- 고정 의미 아이콘: 전화(`call`), 지구본(`web`), 종(`reminder`), 달력(`integration_action`·캘린더), 반복, 손(내 차례·승인), 녹화 꺼짐(기록 중지), 방패(신뢰 줄), 물음표 원(확인 못 함), 체크 원(달성), 반쯤 찬 원(일부), 느낌표 원(실패).

### 4.6 일러스트 방침

- **캐릭터·마스코트·사람 얼굴을 쓰지 않는다.** AI를 사람으로 착각하게 하지 않는다는 원칙(02 §4.1 Generative AI, 02 §4.3 Mental Models)과 "사람인 척 통화하지 않는다"는 약속(03 §2.2)을 시각에서도 지킨다.
- 빈 상태와 온보딩은 지름 64의 원 안에 단색 아이콘 하나를 둔다(현행 `MessageView` 방식). 온보딩의 "할 수 있는 일"은 아이콘 + 짧은 문장 목록으로 그린다.
- 사진·3D·그라데이션 장식을 쓰지 않는다. 앱 용량과 다크 모드 대응 부담을 줄이고, 시각 정체성은 색 두 짝(`live`·`attention`)과 단계 타임라인 모양으로 만든다(02 §7.2 C12).
- **예외(2026-11-26, 06 DR-10): AI Orb.** 비서의 시그니처인 Iridescent Orb(CMP-35)에만 그라데이션을 쓴다. Orb는 추상 구체이며 얼굴·표정이 없다(첫째 줄 원칙 유지). 쓰는 곳은 가운데 비서 버튼, AI 비서 화면, 통화 중 화면, 브리핑 카드, 온보딩 첫 장으로 한정한다.

### 4.8 다크 모드

- 기기 설정을 따른다(앱 안 별도 선택은 SCR-M09에서 "기기 설정 따름 / 밝게 / 어둡게", 기본 "기기 설정 따름"). 03 F-SET-05 범위 안의 화면 설정이다.
- **몰입형 다크(2026-11-26, 06 DR-9).** AI 비서(SCR-A01)와 통화 중(SCR-T08), 온보딩 첫 장(SCR-O01)은 기기 설정과 관계없이 늘 다크(06 §3.3 다크 값)로 그린다. 통화 중 화면의 승인 시트는 밝은 시트로 띄워 결정 순간을 분리한다. 그 밖의 화면은 기기 설정을 따른다.
- 모든 분위기 짝은 밝은·어두운 값을 따로 가진다(현행 `ToneColors`). 새로 추가하는 배지·선 토큰도 두 모드 값을 같이 정한다.
- 웹 페이지(SCR-T03) 내용은 사이트가 정하므로 테마를 입히지 않는다. 앱이 그리는 띠·테두리·행동 기록만 테마를 따른다.
- 잠금 화면 진행 표시는 OS가 정한 배경에 맞춰 밝은·어두운 두 벌을 둔다(§9.3).

### 6.1 탭 바 사양

> **개정(2026-11-26, 06 DR-2).** 아래 원래 사양 가운데 탭 구성·아이콘·라벨·배지 이름이 다음과 같이 바뀐다. 다시 누름·숨김·장소 탭 규칙은 그대로다.
>
> | 항목 | 개정 사양 |
> |---|---|
> | 칸 | `오늘`(SCR-H01) · `업무`(SCR-T01) · **가운데 비서 버튼**(SCR-A01을 엶, 탭 아님) · `기록`(SCR-R01) · `내 정보`(SCR-M01), 이 순서로 고정 |
> | 아이콘 | 오늘: 해 / 업무: 체크 목록 / 가운데: Orb(지름 52, 탭 바 위로 20 솟음) / 기록: 되감기 시계 / 내 정보: 사람 윤곽. 선택된 탭은 인디고 글자 + 옅은 인디고 채움 |
> | 배지 | **업무 탭에만**, 값 = 승인 대기(내 차례) 수. 규칙은 원래와 같음 |
> | 가운데 버튼 | 누르면 AI 비서를 전체 화면 모달로 연다. 닫으면 원래 탭으로. 길게 누르면 바로 듣기 시작(가정, 사용성 테스트로 확정) |
> | 큰 글자 | 다섯 칸이 360 폭에 들어가도록 라벨은 두 글자~세 글자로 고정(DOD-9의 1.5배 상한 유지) |
> | 숨김 | 원래 숨김 화면 + AI 비서(SCR-A01), 통화 중(SCR-T08) |

| 항목 | 사양(원래) | 근거 |
|---|---|---|
| 탭 | `홈`(SCR-H01) · `작업함`(SCR-T01) · `내 정보`(SCR-M01), 이 순서로 고정 | 03 §5.1 A안, 02 §4.2(3~5개) |
| 아이콘 | 홈: 집 / 작업함: 목록 상자 / 내 정보: 사람 윤곽. 선택 시 채운 모양 + `primary` 색 + 라벨 굵게 | §4.5 |
| 라벨 | 항상 표시(아이콘만 두지 않음) | 02 §4.1 Tab bars |
| 배지 | **작업함에만**, 값 = "내 차례" 작업 수(`waiting_user` + 알림이 필요한 `awaiting_confirmation`). 10 이상은 "9+". 0이면 숨김. 새 결과(F-INBOX-03)는 배지에 넣지 않음 | 03 F-INBOX-02, 02 §5 P20, 02 §4.1("배지는 중요한 정보에만") |
| 탭 다시 누름 | 현재 탭을 다시 누르면 그 탭의 첫 화면으로, 이미 첫 화면이면 맨 위로 스크롤 | 플랫폼 관례(가정) |
| 숨김 | 전체 화면 작업 화면(SCR-T03·T04), 온보딩(SCR-O01~O04)에서는 탭 바를 숨긴다 | 한 화면 한 결정 |
| 장소 탭 | 두지 않는다. 검색 제휴 확보 뒤 03에서 다시 정한다 | 03 §5.1 이유 3 |

### 6.2 탭별 화면 트리

> **개정(2026-11-26).** 기준 트리는 03 §5.2의 개정 화면 트리다. 아래 원래 트리의 "홈 부탁 흐름(카드 쌓기)"은 AI 비서(SCR-A01)에서 시작하는 화면 이동으로 바뀌었고(§17.1), 작업함은 업무(승인 요청·진행 중·반복)와 기록(끝난 업무)으로 나뉘었다. 이동 규칙(§6.3)의 "흐름 안 카드 쌓기" 행은 "푸시(같은 모달 스택)"로 읽는다: A01 → H02 → H04 → T02.

### 6.3 화면 이동 규칙

| 이동 방식 | 언제 쓰나 | 해당 화면 |
|---|---|---|
| **흐름 안 카드 쌓기** | 부탁 한 건의 결정을 차례로 받을 때. 앞 카드는 한 줄 요약으로 접히고 [바꾸기]로 다시 펼침 | H01 → H02 → H04 → 진행 카드 |

## 7. 핵심 화면 상세 설계

각 화면은 목적 · 진입 경로 · 와이어프레임 · 요소 우선순위 · 상태별 변화 · 주요 문구 · 관련 기능 · 접근성 메모 순서로 적는다.

### 7.1 SCR-H01 홈

> **개정(2026-11-26).** 홈은 "오늘"(Today 대시보드)로 바뀌었다. 기준 설계는 §17.2다. 아래 원래 설계의 입력칸·예시 칩은 AI 비서 화면(§17.4)으로, 내 차례·진행 중 묶음은 오늘 화면의 "확인이 필요해요"·"진행 중"으로 옮겨졌다.

- **목적(원래)**: 무엇을 맡길지 한 문장으로 받는다. 내 차례·진행 중 작업이 있으면 바로 보이게 한다.
- **진입**: 앱 아이콘(항상 홈), 홈 탭, 온보딩 완료.

```
┌──────────────────────────────────────┐
│ 콜비                                  │
│                                      │
│ 무엇을 맡길까요?                      │ headlineSmall
│ ┌──────────────────────────────────┐ │
│ │ 예: 금요일 7시 2명, 라 파스타     │ │
│ │ 예약해 줘                         │ │
│ │                   [마이크] [보내기]│ │
│ └──────────────────────────────────┘ │
│ (금요일 7시 2명 예약)(영업시간 문의) │ 예시 칩
│ (매일 밤 출석 알림)                   │
│                                      │
│ 내 차례 1                             │ 있을 때만
│ ┃[전화] 라 파스타                     │ attention 막대
│ ┃ 예약금 확인이 필요해요   0:42 남음 >│
│                                      │
│ 진행 중                               │ 있을 때만
│  [전화] 미용실 · 통화 중  ●─●─◉─○  > │ live 칩
│                                      │
│ 최근 장소                             │
│ (라 파스타)(우리 동네 치과)(미용실)   │ 최대 3
├──────────────────────────────────────┤
│  [홈]        [작업함 1]     [내 정보] │
└──────────────────────────────────────┘
```

- **요소 우선순위**: ① 입력칸 ② 내 차례 ③ 진행 중 ④ 예시 칩 ⑤ 최근 장소. 내 차례가 있으면 화면 읽기 순서에서는 입력칸 다음에 오지만, 시각적으로 입력칸 바로 아래에 두어 첫 화면 안에 들어오게 한다.
- **상태별 변화**

| 상태 | 화면 |
|---|---|
| 빈 상태(첫 사용) | 내 차례·진행 중·최근 장소 없음. 입력칸 아래에 "할 수 있는 일" 3가지(전화로 예약·문의·변경 / 결과를 일정·지도로 / 마감 알림) + 예시 칩(02 §5 P26) |
| 로딩 | 입력칸은 즉시 쓸 수 있음. 내 차례·진행 중 자리는 뼈대 행 1줄 |
| 오류(서버 연결 안 됨) | 입력칸 위 얇은 알림 줄 "잠시 연결이 안 돼요. 다시 시도해 주세요 [다시 시도]". 입력은 막지 않고 보내기 시 같은 안내 |
| 진행 | 진행 중 묶음에 작업 카드(CMP-10), 단계 점 |
| 완료 | 끝난 작업은 홈에 남지 않고 작업함 "끝남"으로. 방금 흐름에서 끝난 작업만 흐름 안 결과 요약으로 보임(D-2) |
| 받아쓰기 중 | 입력칸 테두리 `primary`, 마이크 버튼이 [멈춤]으로, 입력칸 안 "듣고 있어요" |

- **주요 문구**: "무엇을 맡길까요?", "내 차례", "진행 중", "최근 장소", 빈 상태 제목 "귀찮은 전화, 대신 걸어 드릴게요"(현행 문구의 띄어쓰기만 고침).
- **관련 기능**: F-REQ-01·02·03·04(Ph2)·07, F-INBOX-02, F-CALL-03, F-PLACE-04·05(Ph2).
- **접근성**: 화면 읽기 순서 = 제목 → 입력칸 → 마이크 → 보내기 → 예시 칩 → 내 차례 → 진행 중 → 최근 장소 → 탭 바. 내 차례 행의 라벨 "내 차례, 라 파스타, 예약금 확인이 필요해요, 42초 남음". 남은 시간은 홈에서는 10초 단위로만 갱신(매초 다시 그리지 않음, 가정).

### 7.2 홈 부탁 흐름과 SCR-H02 장소 후보

- **목적**: 장소 조건만 있는 부탁에서 전화할 곳 하나(비교는 여럿)를 고르게 한다.
- **진입**: H01에서 보내기(장소 미정), 결과·실패 화면의 [다른 곳 찾기](F-RES-07), 공유 시트(Ph2).

```
┌──────────────────────────────────────┐
│ [←] 새 부탁                           │
│ 강남역 근처 파스타집, 금요일 7시 2명  │ 보낸 부탁 줄
│ 예약해 줘                     [고치기]│
│                                      │
│ 강남역 근처 파스타집 4곳을 찾았어요   │
│ ┌──────────────────────────────────┐ │
│ │ 라 파스타            양식 · 350m  │ │
│ │ 서울 강남구 ○○로 12               │ │
│ │ 02-111-0000                       │ │
│ │ 부탁한 위치에서 가장 가까워요     │ │ 추천 이유
│ │ [상세]                  [여기로]  │ │
│ └──────────────────────────────────┘ │
│ ┌──────────────────────────────────┐ │
│ │ 파스타 하우스        양식 · 600m  │ │
│ │ ...                               │ │
│ └──────────────────────────────────┘ │
│ 장소 정보는 카카오 로컬 검색 결과예요 │ 출처 한 줄(가정)
│ 찾는 곳이 없나요?                     │
│ [다시 찾기]          [번호 직접 입력] │
└──────────────────────────────────────┘
```

- **요소 우선순위**: ① 후보 카드의 이름·거리 ② [여기로] ③ 추천 이유 ④ 다시 찾기·번호 직접 입력.
- **추천 이유 규칙**: 검색 응답에 있는 값(거리, 분류, 검색어 일치, 사용자가 전에 통화한 곳)으로만 쓴다. 리뷰·평점처럼 받지 않은 근거는 쓰지 않는다(03 F-PLACE-01, 01 §6.4). 후보는 3~5곳(F-PLACE-02).
- **상태별 변화**

| 상태 | 화면 |
|---|---|
| 로딩 | "강남역 근처 파스타집을 찾는 중이에요" + 뼈대 카드 3개 |
| 위치 필요("근처") | 후보 대신 위치 사전 안내 시트(CMP-23): "근처 가게를 찾으려면 지금 위치가 필요해요" [계속]. 거부 시 "동네 이름을 알려 주세요" 한 칸 질문(F-REQ-06) |
| 결과 없음 | 빈 상태 "조건에 맞는 곳을 찾지 못했어요" + [조건 바꿔 다시 찾기] [번호 직접 입력] (02 §5 P2 "결과 없음도 진입점") |
| 번호 없는 후보 | 카드는 보이되 [여기로] 비활성, "전화번호가 없어요" |
| 오류 | "장소를 찾지 못했어요. 잠시 뒤 다시 시도해 주세요 [다시 시도]" |
| 선택 완료 | 카드 목록이 "라 파스타 · 350m [바꾸기]" 한 줄로 접히고 아래에 계획 카드가 쌓임 |
| 여러 곳 선택(Ph2) | 카드에 체크 상자, 하단 고정 [2곳에 차례로 물어보기] |

- **관련 기능**: F-PLACE-01·02·03, F-CALL-06(Ph2), F-REQ-06·07.
- **접근성**: 카드 하나가 버튼 하나(라벨에 이름·분류·거리·번호 유무). [상세]는 별도 버튼. 결과 개수 문장은 로딩이 끝날 때 실시간 영역으로 한 번 읽음.

### 7.3 SCR-H03 장소 상세(시트)

- **목적**: 고르기 전 한 곳의 정보를 확인하고, 거기에 물어보거나 길을 찾는다.
- **진입**: H02 [상세], H01 최근 장소, T05 장소 이름.

```
┌──────────────────────────────────────┐
│            ───                        │ 시트 손잡이
│ 라 파스타                     [닫기] │
│ 양식 · 350m                           │
│ 서울 강남구 ○○로 12                   │
│ 02-111-0000              [번호 복사] │
│ 지난번 통화: 11월 20일                │ 최근 장소일 때
│ ┌ (Ph2) 이곳은 온라인 예약이 돼요 ─┐ │
│ │ [온라인 예약으로]                 │ │
│ └──────────────────────────────────┘ │
│ [길찾기]                              │
│ [          여기에 물어보기          ] │ 주 버튼
└──────────────────────────────────────┘
```

- **상태**: 기본 / 정보 불러오기 실패("정보를 불러오지 못했어요") / 온라인 예약 안내(Ph2, F-PLACE-06: 안내만 하고 선택은 사용자, 03 OD-13).
- **관련 기능**: F-REQ-07, F-PLACE-04·06, F-INTG-04.
- **접근성**: 열릴 때 제목에 초점, 닫으면 연 요소로 초점 복귀.

### 7.4 SCR-H04 계획 카드

- **목적**: 실행 전에 오해를 잡고, [이대로 시작] 한 번으로 맡긴다.
- **진입**: 홈 흐름(장소 선택 후, 또는 대상·번호가 확정된 부탁), H03 [여기에 물어보기], T05 [다시 걸기]·[조건 바꿔 다시], 공유 시트(Ph2).

```
┌──────────────────────────────────────┐
│ [←] 이렇게 진행할게요                 │
│ [전화] 전화로 예약해요                │ 작업 종류 줄
│ ┌ 확인해 주세요 ───────────────────┐ │
│ │ 전화할 곳  라 파스타        [수정]│ │
│ │ 번호       02-111-0000      [수정]│ │
│ │            검색 결과에서 찾은 번호 │ │ 출처 라벨
│ │ 부탁할 일  11월 28일(금) 오후 7시 │ │
│ │            2명 예약         [수정]│ │
│ │ 조건       (8시도 괜찮아요 ×)     │ │
│ │            (+ 조건 추가)          │ │
│ │ 상대에게 알려 줄 정보             │ │
│ │            예약자명 김지은 · 내 정보│
│ │            연락처 010-****-1234   │ │
│ │                             [수정]│ │
│ └──────────────────────────────────┘ │
│ 한국어로, 김지은 이름으로 걸어요   > │ 접힌 요약 줄
│ 반복하거나 알림으로 받기           > │ → H06
├──────────────────────────────────────┤
│ 보통 3~5분 걸려요. 끝나면 알려 드릴게요│ 예상 시간
│ [방패] 통화 첫마디에 AI 비서라고 밝혀요│ 신뢰 줄
│ [            이대로 시작            ] │ 주 버튼
└──────────────────────────────────────┘
```

- **펼침 규칙(D-4)**: 값의 출처가 "부탁 해석"·"검색"·"공유 글"이면 펼친다. 출처가 "내 정보"·"기본값"이면 접는다. 해석이 휴리스틱(LLM 없이 정리)이면 모든 칸을 펼치고 "AI 없이 간단히 정리했어요. 내용을 확인해 주세요"를 둔다(UX-001 §7.2 유지).
- **변형**: 웹 작업(Ph2)은 "부탁할 일" 아래에 단계 목록(사이트 열기 → 로그인(직접) → 신청서 작성 → 제출 직전 확인)과 "사이트에 입력할 정보"를 둔다(03 §6 흐름 2-3). 메일 읽기(Ph2)는 "읽을 범위(기간·보낸 사람)" 칸을 펼친다(03 §6 흐름 7-3).
- **요소 우선순위**: ① [이대로 시작] ② 전화할 곳·번호 ③ 부탁할 일 ④ 상대에게 알려 줄 정보 ⑤ 조건 ⑥ 접힌 줄.
- **상태별 변화**

| 상태 | 화면 |
|---|---|
| 계획 세우는 중 | 카드 자리에 뼈대 행 3개, "계획을 세우는 중이에요" |
| 번호 없음 | 카드 맨 위에 번호 한 칸(자동 초점, 전화 키패드) + "번호만 알려 주시면 바로 걸게요"(F-REQ-06). [이대로 시작] 비활성, 이유 "전화번호가 필요해요" |
| 수정 중 | 해당 행이 그 자리에서 입력칸으로(움직임 `medium`) |
| 걸 수 없는 번호 | 번호 행에 `critical` 글자 "긴급·특수 번호에는 걸 수 없어요"(F-TRUST-05), 시작 비활성 |
| 수신 거부 번호(F-CALL-09) | "이곳은 AI 전화를 받지 않겠다고 했어요" + [번호 복사] [전화 앱 열기] |
| 한도 가까움 | 예상 시간 줄 위 "이번 달 1건 남았어요"(F-ACCT-03) |
| 시작 처리 중 | 주 버튼 진행 표시·비활성(REQ-007) |
| 첫 시작 | §7.5 |
| 시작됨 | 카드가 "라 파스타에 예약 전화 · 계획 확인함" 한 줄로 접히고 진행 카드가 쌓임 |

- **관련 기능**: F-CALL-01, F-APPR-01, F-NOTI-05, F-REQ-06, F-INTG-05, F-MEM-03·05, F-TRUST-01·05, F-CALL-09.
- **접근성**: 행마다 "제목, 값, 출처, 수정 버튼" 순으로 읽음. 접힌 줄 라벨 "통화 언어 한국어, 내 이름 김지은, 펼치기". 하단 고정 영역은 큰 글자에서 내부 스크롤.

### 7.5 첫 작업 전 안내(SCR-H04의 첫 시작 상태)

- **목적**: 첫 통화 직전의 확인을 한 번으로 줄이면서 알림 권한을 받는다(02 §7.2 C5, 03 §6 흐름 1-5).
- **설계**: 신뢰 약속은 온보딩 SCR-O02로 옮겼으므로 여기서는 다시 묻지 않는다. 첫 [이대로 시작]을 누르면 작업은 **바로 시작**되고, 동시에 알림 사전 안내 시트가 올라온다. 사용자가 시트를 닫거나 거부해도 작업은 진행된다.

```
┌──────────────────────────────────────┐
│            ───                        │
│ [종] 확인할 일이 생기면 알려 드릴게요 │
│ 통화 중에 예약금처럼 직접 정해야 할   │
│ 일이 생기면 바로 알림을 보내요.       │
│ 알림이 없으면 앱을 열어 두셔야 해요.  │
│ [              계속              ]    │ 버튼 하나 → OS 권한 창
└──────────────────────────────────────┘
```

- **상태**: 허용 → 시트 닫힘 / 거부 → 진행 카드 위에 "알림이 꺼져 있어요. 확인 요청을 놓치지 않게 화면을 켜 두세요 [설정 열기]" 한 줄(§14 PR-2) / 이미 결정됨 → 시트 생략.
- **관련 기능**: F-NOTI-02, F-APPR-01, 02 §5 P24, 02 §4.1 Privacy.
- **접근성**: 시트가 나타나면 제목에 초점, [계속] 하나만 있어 순서가 단순.

### 7.6 SCR-H05 번호 입력·연락처 선택(시트)

- **목적**: 번호를 모를 때 가장 쉬운 방법으로 하나를 채운다.
- **진입**: H04 번호 칸, H02 [번호 직접 입력].
- **구성**: 번호 입력칸(자동 초점) → [연락처에서 고르기](OS 선택기, 고른 한 항목만 전송, F-INTG-05) → 최근 번호 3개 → [완료].
- **상태**: 입력 중 / 형식 오류("번호를 다시 확인해 주세요") / 걸 수 없는 번호 / 연락처 권한 거부(선택기는 권한 없이 쓸 수 있는 플랫폼이면 그대로, 아니면 사전 안내 후 거부 시 "직접 입력해 주세요") / 완료 → H04 번호 행 갱신, 출처 "직접 입력" 또는 "연락처".
- **관련 기능**: F-REQ-06, F-INTG-05, F-TRUST-05.
- **접근성**: 오류 문구는 입력칸 설명으로 연결해 읽힘.

### 7.7 SCR-H06 반복·알림 설정(시트)

- **목적**: 부탁을 반복 작업이나 마감 알림으로 저장한다.
- **진입**: H04 [반복하거나 알림으로 받기], 반복으로 해석된 부탁(03 §6 흐름 3-2: 계획 카드 대신 이 시트가 바로 열림).

```
┌──────────────────────────────────────┐
│            ───                        │
│ ○○앱 출석 알림                        │
│ 반복   (매일)(매주)(매월)             │
│ 시각   오후 9:00                  >   │
│ ┌──────────────────────────────────┐ │
│ │ [종] 알림을 드리고, 출석은 직접   │ │ L0 안내(neutral)
│ │ 해 주세요. 누르면 앱을 바로 열어요│ │
│ └──────────────────────────────────┘ │
│ [              저장              ]    │
└──────────────────────────────────────┘
```

- **변형**: 반복 전화(Ph2, F-ROUT-04)는 안내를 "매번 걸기 전에 먼저 물어볼게요. 답이 없으면 그 회차는 건너뛰어요"로 바꾼다(C-8).
- **상태**: 기본 / 저장 중 / 저장됨(토스트 "작업함 반복에 넣었어요") / 실패.
- **관련 기능**: F-ROUT-01·02·04, C-8.
- **접근성**: 반복 칩은 단일 선택 그룹으로 읽힘.

### 7.8 SCR-T01 작업함

> **개정(2026-11-26).** 작업함은 "업무"로 이름을 바꾸고, 끝남 묶음을 기록 탭(SCR-R01)으로 옮겼다. 기준 설계는 §17.5(업무)·§17.7(기록)이다. 아래 원래 설계의 내 차례·진행 중·반복 묶음 규칙과 행 컴포넌트(CMP-10)는 그대로 쓴다.

- **목적(원래)**: 모든 작업을 상태별로 한곳에서 보고, 내 차례를 놓치지 않게 한다.
- **진입**: 작업함 탭, 진행 카드·알림(탭 전환), T02·T05 뒤로.

```
┌──────────────────────────────────────┐
```

- **요소 우선순위**: 내 차례 > 진행 중 > 끝남 > 반복(03 F-INBOX-01 순서). 묶음이 비면 제목째 숨긴다(반복은 비어도 "반복할 일을 만들면 여기에 모여요" 한 줄).
- **상태별 변화**

| 상태 | 화면 |
|---|---|
| 빈 상태 | "아직 맡긴 일이 없어요" + 예시 칩 하나 + [홈에서 맡기기](02 §5 P26) |

| 오류 | 빈 상태 오류 변형 + [다시 시도]. 캐시된 목록이 있으면 위에 "최신 상태가 아닐 수 있어요" |
| 진행 | 진행 중 행이 단계 바뀔 때 칩만 교차 페이드 |

- **관련 기능**: F-INBOX-01~04, F-ROUT-02, 03 §7.2 상태 묶음.
- **접근성**: 묶음 제목은 머리글. 행 사용자 정의 동작(지우기·일시정지). 배지 수와 내 차례 묶음 수가 같아야 함(§13.3 검사).

### 7.9 SCR-T02 작업 상세 — 진행 중(통화)과 승인 카드

> **개정(2026-11-26).** 이 화면은 둘로 나뉘었다. 단계 진행과 승인 카드는 **업무 실행 화면(SCR-T02, §17.6)**이, 대화 기록(실시간 자막)·끊기·승인 시트는 **통화 중 화면(SCR-T08, §17.6)**이 맡는다. 아래 원래 설계의 승인 카드 동작(CMP-15)·남은 시간·만료·알림 진입 규칙은 두 화면 모두에 그대로 적용한다.

- **목적(원래)**: 지금 어느 단계인지, 상대와 무슨 말을 하는지 보여 주고, 결정이 필요할 때 바로 답하게 한다.
- **진입**: 홈 진행 카드, T01 진행 중·내 차례 행, 내 차례 알림, 잠금 화면 [열기].

```
┌──────────────────────────────────────┐
│ [←] 라 파스타                  [끊기] │ 끊기 = critical 글자
│ 11월 28일(금) 오후 7시 2명 예약       │
│ 준비   거는 중   통화 중   결과 정리  │
│  ●───────●───────◉───────○      1:24 │ live
│ [방패] AI 비서라고 밝히고 통화해요 ·  │
│ 대화는 글로 기록돼요                  │
│ ┌ 대화 ────────────────────────────┐ │
│ │ AI   안녕하세요. 김지은 님을 대신해│ │
│ │      전화드린 AI 비서예요...       │ │
│ │ 상대 네, 말씀하세요.               │ │
│ │ 상대 예약금 만 원이 있어요.        │ │
│ │          [새 대화 2줄 ↓]           │ │
│ └──────────────────────────────────┘ │
├──────────────────────────────────────┤
│ ┌ [손] 확인이 필요해요     0:42 ───┐ │ attention, 테두리
│ │ 예약금 10,000원을 내야 예약돼요.  │ │ titleMedium
│ │ 진행할까요?                       │ │
│ │ 상대방이 잠시 기다리고 있어요.    │ │
│ │ 허락할 금액                       │ │
│ │ (10,000원까지)(15,000원까지)      │ │ 금액 상한 칩
│ │ (금액 직접 입력)                  │ │
│ │ (다른 시간도 물어봐 줘)           │ │ 빠른 답
│ │ [조건 덧붙이기 (선택)           ] │ │
│ │ 답이 없으면 진행하지 않아요.      │ │
│ │ 카드번호·비밀번호는 적지 마세요.  │ │
│ │ [  거절  ]  [10,000원까지 승인]   │ │
│ └──────────────────────────────────┘ │
└──────────────────────────────────────┘
```

- **승인 카드 변형(CMP-15)**

| `pendingAction.kind` · 확인 지점 | 질문 예 | 고유 요소 |
|---|---|---|
| `decision` · C-3 | "토요일 오후 2시로 바꿔도 될까요?" | 빠른 답 칩 3개 + 코멘트 |
| `spend_cap` · C-1 | "예약금 10,000원을 내야 예약돼요. 진행할까요?" | 상한 칩: 요청 금액 그대로(기본 선택) · 한 단계 위(반올림, 가정) · 직접 입력. 주 버튼이 "[N원까지 승인]". 상한을 넘으면 다시 묻는다고 한 줄 안내 |
| `decision` · C-6 | "회원번호 1234를 알려 줘도 될까요?" | 알려 줄 값을 그대로(일부 가림 없이, 사용자가 무엇을 주는지 알도록) 보이고 출처 라벨 |
| `decision` · C-2 | "24개월 약정으로 바꾸면 월 5,000원 할인돼요. 진행할까요?" | 조건 요약 칸, 코멘트 칸을 처음부터 펼침 |

- **요소 우선순위**: 승인 카드가 있으면 ① 질문 ② [승인]/[거절] ③ 남은 시간 ④ 상한·빠른 답 ⑤ 타임라인 ⑥ 대화. 없으면 ① 타임라인 ② 대화 ③ [끊기].
- **상태별 변화**

| 상태 | 화면 |
|---|---|
| 준비·거는 중 | 대화 빈 상태 "대화를 기다리고 있어요 · 상대방이 받으면 여기에 나타나요" |
| 통화 중 | 대화 실시간, 자동 따라가기(사용자가 위로 올리면 멈추고 [새 대화 N줄] 표시) |
| 내 차례 | 하단 승인 카드, 강한 진동(REQ-007), 상태 칩 "승인 대기" |
| 응답함 | 승인 카드가 결정 기록 한 줄("10,000원까지 승인함 · 오후 3:12")로 접혀 대화 위로 |
| 만료 | 카드가 `neutral`로 바뀌며 "시간이 지나 진행하지 않았어요", 대화에 사용자 안내 줄 |
| 끊기 | [끊기] → 확인 시트 "통화를 끊을까요? 지금까지 내용으로 결과를 정리해요" [끊기](critical) [계속 통화] |
| 결과 정리 | 타임라인 4단계 현재, "결과 정리 중이에요" |
| 끝남 | 같은 화면이 위로 스크롤되며 T05 구성으로 바뀜(UX-001 §6 `slow`) |
| 연결 실패 | `critical` 결과로 바로 전환, F-RES-07 다음 길 |

- **관련 기능**: F-CALL-02·03·04, F-APPR-02·03·04·05, F-TRUST-01·04, F-NOTI-03, C-1·C-2·C-3·C-6.
- **접근성**: 읽기 순서 = 제목 → 부탁 요약 → 타임라인 → 신뢰 줄 → 대화 → 승인 카드(나타나면 초점 이동 없이 실시간 영역으로 알림, 사용자가 원할 때 이동할 수 있게 "승인 카드로 이동" 접근성 동작 제공). 남은 초는 읽기 제외, 30·10초 알림(UX-001 REQ-012).

### 7.10 SCR-T03 웹 작업 화면(Phase 2)

- **목적**: AI가 사용자의 기기 안 브라우저에서 칸을 채우는 동안 무엇을 하는지 보이게 하고, 제출은 사용자가 직접 누르게 한다.
- **진입**: H04 [이대로 시작](웹 작업), 마감 알림의 "콜비로 열기"(F-ROUT-03), 작업함 내 차례.

```
┌──────────────────────────────────────┐
│ [닫기] 구청 체육관 대관 신청    [중지]│
│▒ [live] 콜비가 입력하고 있어요 ·     ▒│ AI 조작 띠
│▒ 화면을 켜 두세요                    ▒│
│┏━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┓│ 3px live 테두리
│┃                                  ┃│
│┃          (웹 페이지)             ┃│
│┃                                  ┃│
│┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛│
│ 기록  날짜를 12월 13일로 골랐어요  ▲ │ 행동 기록(펼치면 전체)
└──────────────────────────────────────┘
```

- **제출 단계(C-4, CMP-16)**: 띠가 `attention`으로 바뀌고 "제출 버튼은 직접 눌러 주세요". 아래에서 입력 요약 시트(이름·날짜·시간·인원)가 반쯤 올라오고, 사이트의 제출 버튼 위치에 강조 테두리를 그린다. 사용자가 사이트 버튼을 누르면 완료 화면 스크린숏을 증거로 남기고(F-WEB-05) T05로.
- **상태별 변화**

| 상태 | 화면 |
|---|---|
| 허용 목록 밖 사이트 | 시작 전 H04에서 "아직 이 사이트는 맡을 수 없어요 [사이트 바로 열기]"(F-WEB-02) |
| 여는 중 | 타임라인 "사이트 여는 중", 페이지 영역 뼈대 |
| 조작 중 | `live` 띠·테두리, 사용자 터치는 페이지에 전달하지 않고 "지금은 콜비가 입력 중이에요. [중지]를 누르면 직접 할 수 있어요" 안내 (사용자와 AI 조작을 섞지 않음, 02 §3.5) |
| 앱을 떠남 | 작업 `paused`, 알림 "돌아오면 이어서 할게요"(03 §6 흐름 2-4). 돌아오면 띠 `neutral` "멈췄어요 [이어서 하기]" |
| 손 넘기기 | §7.11 |
| 페이지 속 지시 감지 | 행동 기록에 "페이지에 있는 안내는 따르지 않았어요" 한 줄(F-WEB-06) |
| 실패 | 사이트 오류 문구를 그대로 인용 + 다음 길 |

- **관련 기능**: F-WEB-01·02·03·04·05·06, F-APPR-07, F-ROUT-03.
- **접근성**: 띠 문구 변경은 실시간 영역. 행동 기록은 펼친 상태에서 목록으로 읽힘. 웹 페이지 자체의 접근성은 사이트에 따름(한계로 명시).

### 7.11 SCR-T04 손 넘기기(Phase 2)

- **목적**: 로그인·본인 인증·결제 정보·Captcha를 사용자가 직접 하게 하고, 그동안 기록하지 않음을 보인다.
- **진입**: T03에서 해당 화면 도달, 내 차례 긴급 알림.

```
┌──────────────────────────────────────┐
│▒ [손] 여기서부터는 직접 해 주세요     ▒│ attention 띠
│▒                          남은 8:10  ▒│
│ 본인 인증은 직접 하셔야 해요.         │ 이유
│ [녹화 꺼짐] 지금 화면은 기록하지 않아요│ 기록 중지
│┌────────────────────────────────────┐│ 테두리 없음
││                                    ││
││        (웹 페이지: 사용자가 조작)   ││
││                                    ││
│└────────────────────────────────────┘│
├──────────────────────────────────────┤
│ [ 그만두기 ]   [  다 했어요, 이어서  ]│
└──────────────────────────────────────┘
```

- **요소 우선순위**: ① 이유 ② 기록 중지 표시 ③ [다 했어요, 이어서] ④ 남은 시간 ⑤ [그만두기].
- **상태별 변화**: 시작(띠 교차 페이드 `fast`, 강한 진동 없음 — 승인과 구분) / 사용자 조작 중 / 본인 인증 앱 전환 후 복귀(같은 화면 유지, 가정: WebView 전환 용이성 03 A-5) / 남은 시간 1분(띠에 "1분 남았어요") / 시간 지남(작업 멈춤, 내 차례에 "본인 인증을 기다리고 있어요"로 남음, 03 §6 흐름 2-6) / [이어서] → `live` 띠로 복귀 / [그만두기] → 확인 후 T05 취소 결과.
- **관련 기능**: F-APPR-06, NFR-SEC-01·02, C-5.
- **접근성**: 패널 등장 시 "직접 해 주세요. 지금 화면은 기록하지 않아요" 한 번 알림. 하단 버튼은 큰 글자에서 세로 쌓기([그만두기] → [다 했어요, 이어서]).

### 7.12 SCR-T05 결과

- **목적**: 무엇이 확인됐고 무엇이 아닌지 알리고, 다음 일로 바로 잇는다.
- **진입**: T02 통화 종료(같은 화면 전환), 완료 알림, T01 끝남 행, 홈 흐름 결과 요약.

```
┌──────────────────────────────────────┐
│ [←] 라 파스타                  [삭제] │
│ ┌ (positive) ──────────────────────┐ │
│ │ [체크] 예약됐어요                 │ │ titleMedium
│ │ 11월 28일(금) 오후 7시 · 2명      │ │
│ │ 예약자명 김지은                   │ │
│ │ 확인된 것                         │ │
│ │  · 예약금 없음  · 2시간 이용      │ │
│ │ 확인 못 한 것                     │ │
│ │  · 주차 가능 여부                 │ │
│ │ 다음 할 일                        │ │
│ │  · 10분 전에 도착해 주세요        │ │
│ │ [방패] AI 비서가 통화해 정리했어요│ │
│ └──────────────────────────────────┘ │
│ [         캘린더에 추가          ]    │ 주 행동
│ [길찾기]    [공유]    [다시 걸기]     │ 보조 최대 3
│ 근거  "네, 7시 두 분 예약됐어요" >    │ 대화 발췌(F-RES-04 이전엔 대화 기록 링크)
│ 결정 기록 1건 >                       │
│ 부탁한 일 >                           │
│ 대화 전체 >                           │
└──────────────────────────────────────┘
```

- **주 행동 선택 규칙(DOD-6)**: 확정된 일정(`appointment`)이 있으면 [캘린더에 추가](Ph1 기기 캘린더, 권한 거부 시 [일정 파일 저장]) → 장소가 있고 일정이 없으면 [길찾기] → 그 밖에는 [공유]. 실패·확인 못 함이면 주 행동은 F-RES-07의 첫 길([직접 걸기] 또는 [다시 걸기]). 서버의 `suggestedActions` 순서가 있으면 그것을 따른다(03 §7.4).
- **상태별 변화**

| 결과 | 분위기·아이콘 | 첫 줄 예 | 후속 |
|---|---|---|---|
| `success` | `positive` · 체크 | 예약됐어요 | 캘린더·길찾기·공유 |
| `partial` | `caution` · 반쯤 찬 원 | 8시로만 예약됐어요 | 캘린더·조건 바꿔 다시·공유 |
| `unverified` | `neutral` · 물음표 | 예약됐는지는 확인하지 못했어요 | 다시 걸기·직접 걸기·공유(공유 문구에 "확인 못 함" 포함, F-RES-03) |
| `failed` | `critical` · 느낌표 | 통화가 연결되지 않았어요 / 상대방이 AI 전화는 받지 않는다고 했어요 | 직접 걸기(번호 복사·전화 앱) · 다른 곳 찾기 · 시간 바꿔 다시(F-RES-07, F-CALL-10) |
| `canceled` | `neutral` · 되돌리기 | 작업을 멈췄어요 | 다시 시작 |
| 정리 중 | 뼈대 | 결과 정리 중이에요 | — |
| 비교(Ph2) | 부모 카드 + CMP-20 | 3곳 중 2곳에 재고가 있어요 | 길찾기(곳별) |
| 웹(Ph2) | 결과 + 증거 스크린숏·접수 번호 | 신청서를 냈어요. 접수 번호 A-1234 | 다음 할 일 |
| 메일 일정(Ph2) | 후보 목록 + 체크 상자 | 일정 4건을 찾았어요. 1건은 시간이 없어 확인하지 못했어요 | 고른 일정 캘린더에 추가(C-7) |

- **관련 기능**: F-RES-01·02·03·04·05·07, F-INTG-01·02·04, F-CALL-05·10, F-TRUST-07, F-INBOX-03·04.
- **접근성**: "확인된 것 / 확인 못 한 것 / 다음 할 일"은 머리글. 결과 화면이 나타나면 첫 줄을 실시간 영역으로 한 번 읽음. 색 없이도 아이콘·글자로 결과 구분.

### 7.19 SCR-X01·X02·X03 앱 밖 화면

- X01 잠금 화면 진행 표시·X02 알림은 §9에서 다룬다.
- **SCR-X03 공유 시트로 들어오기(Phase 2)**: 다른 앱에서 공유 → 콜비 공유 시트 "어떤 부분을 보낼까요?" 문단별 체크(기본: 업체명·번호·날짜로 보이는 부분만 선택, 가정) → [이걸로 부탁하기] → 앱이 열리며 H04(대상 확정) 또는 H02. 문구 "고른 부분만 콜비로 보내요"(F-REQ-05, 03 §5.3).

### 7.20 화면 명세 집계

- 상세 명세(와이어프레임 포함): H01, H01 흐름+H02, H03, H04, H04 첫 시작, H05, H06, T01, T02(승인 카드 포함), T03, T04, T05, T06, T07, M01, M03, M04, O01~O04(묶음) — 18개 단위.
- 화면 ID 기준 다룬 화면: SCR-H01~H06(6), SCR-T01~T07(7), SCR-M01~M11(11), SCR-X01~X03(3), SCR-O01~O04(4), 총 **31개**(M02·M05~M11·X03은 요약 표 수준).

## 8. 핵심 흐름별 화면 시퀀스

표기: `→` 같은 흐름 안 카드 쌓기·푸시, `⇢(시트)` 시트, `⇒(탭)` 탭 전환, `↗(외부)` 외부 앱, `▣(모달)` 전체 화면 모달. 탭 수는 앱 안에서 누르는 횟수이며 글 입력·OS 권한 창·잠금 해제는 따로 적는다.

### 흐름 1. 한 줄 부탁 → 장소 찾기 → 계획 확인 → 통화 → 승인 → 결과

```
H01 ─(보내기)→ H02 카드 ─(여기로)→ H04 카드 ─(이대로 시작)→ 진행 카드(H01 흐름)
   [첫 작업이면 ⇢ 알림 사전 안내 시트 → OS 권한 창]
   ─(승인 요청: 앱 안이면 흐름 안 승인 카드 / 앱 밖이면 X02 알림 ⇒(탭) T02)
   ─(승인)→ T02 ─(종료)→ T05(같은 화면) ─(캘린더에 추가)⇢ T06 ─(추가)→ T05
   예외: AI 거절·연결 실패 → T05 실패 변형 → [직접 걸기]↗ / [다른 곳 찾기]→ H02
```

| 경우 | 탭 수 목표 |
|---|---|
| 장소를 찾아 예약 전화(번호 모름) | 입력 1회 + 장소 선택 1회 + 시작 1회 = **3탭** |
| 대상·번호를 아는 부탁 | 입력 1회 + 시작 1회 = **2탭** |
| 통화 중 예약금 승인 | +1탭(칩 기본 선택이 요청 금액이므로 [N원까지 승인] 한 번) |
| 결과를 캘린더에 | +2탭([캘린더에 추가], [추가]). 첫 사용은 +1탭과 OS 권한 창 |

### 흐름 2. 웹 작업과 손 넘기기(Phase 2)

```
H01 ─(보내기)→ H04 카드(웹 변형: 단계·입력할 정보) ─(이대로 시작)▣ T03(live 띠)
   ─(로그인·본인 인증 화면)→ T04(attention 띠, 기록 중지) ─(다 했어요, 이어서)→ T03
   ─(제출 직전)→ T03 제출 안내(CMP-16) ─(사이트 제출 버튼: 사용자)→ T05(증거 첨부)
   앱을 떠나면: T03 paused → X02 "돌아오면 이어서 할게요" → 복귀 시 T03 [이어서 하기]
   허용 목록 밖: H04에서 "아직 이 사이트는 맡을 수 없어요" ↗(사이트 바로 열기)
```

- 탭 수 목표: 입력 1 + 시작 1 + [이어서] 1 + 사이트 제출 1(사용자) = **4탭**(사이트 안 인증 조작 제외).

### 흐름 3. 반복 작업 등록과 알림(출석 포함)

```
등록: H01 ─(보내기)⇢ H06(반복 설정, L0 안내) ─(저장)→ H01 + 토스트 → T01 반복 묶음
회차(Ph1): X02 마감 알림 ─(누름)↗ 대상 앱·사이트
회차(Ph2 지켜보는 실행): X02 ─("콜비로 열기")▣ T03 ─(로그인)→ T04 → T03 → T05
회차(Ph2 반복 전화): X02 실행 전 확인 ⇒(탭) T02 확인 카드 ─(실행)→ T02 통화 → T05
관리: T01 반복 행 → T07(일시정지·시각 변경·삭제)
```

- 탭 수 목표: 등록 = 입력 1 + 저장 1 = **2탭**. 회차(Ph1) = 알림 **1탭**. 반복 전화 회차 = 알림 1 + 실행 1 = **2탭**.

### 흐름 4. 연동 연결(OAuth) 온보딩

```
T05 ─(캘린더에 추가, 처음)⇢ 선택 시트 [이 휴대폰 캘린더] / [Google 캘린더 연결](Ph2)
   기기: ─→ OS 권한 창 ─(허용)→ T06 ─(추가)→ T05
         └(거부)→ "[일정 파일 저장]으로 넣을 수 있어요" + 설정에서 켜는 법
   Google(Ph2): ─→ 범위 안내("일정을 읽고 추가해요") ↗ OAuth 화면 → 복귀 → T06 → T05
관리: M01 → M04 → [해제] → 확인 → "연결 정보를 바로 지웠어요"
Gmail(Ph2): 처음 "메일에서 일정 찾아 줘" → 범위 선택(기간·보낸 사람) → 같은 방식
```

- 탭 수 목표: 첫 기기 캘린더 추가 = [캘린더에 추가] 1 + 선택 1 + OS 허용 + [추가] 1 = **3탭 + OS 창 1**. 이후 = **2탭**.

### 흐름 5. 첫 실행 온보딩

```
O01 ─(다음)→ O02 ─(알겠어요, 다음)→ O04 ─(소셜 로그인 ↗ → 번호 확인 → 동의)→ O03
   ─(이름 입력, 시작하기)→ H01 빈 상태(할 수 있는 일 3가지 + 입력칸)
   권한 요청 0회(알림·위치·연락처·마이크는 처음 쓸 때)
```

- 탭 수 목표: 다음 2 + 로그인 1 + 번호 확인 1~2 + 동의 1 + 시작 1 = **약 7탭**. 첫 실행부터 첫 [이대로 시작]까지 중앙값 2분 이하(03 §11 Phase 1 출시 기준).

### 흐름 6. 앱 밖에서 승인 요청 받기

```
X01 잠금 화면 진행 표시가 "확인 필요"로 바뀜 + X02 내 차례 긴급 알림
   ─(알림 누름, 잠금 해제)⇒(탭) T01 > T02(승인 카드 펼침, 남은 시간 재계산)
   ─(승인 또는 거절)→ T02(결정 기록 한 줄) → 통화 계속
   만료: X02 알림 문구가 "시간이 지나 진행하지 않았어요"로 바뀜, T02 만료 상태
   Ph2: 알림의 [거절] 버튼으로 앱을 열지 않고 거절(F-APPR-08, 03 OD-6 권장안)
```

- 탭 수 목표: 알림 1 + 승인 1 = **2탭**(잠금 해제 별도). 거절은 Ph2부터 알림 버튼 **1탭**.

### 흐름 7. 메일 속 일정 캘린더 등록(Phase 2)

```
H01 ─(보내기)→ [Gmail 미연결이면 흐름 4] → H04 카드(메일 읽기 범위) ─(이대로 시작)
   → 진행 카드(읽는 중) → T05 메일 일정 변형(후보 목록, 확인 못 함·겹침 표시)
   ─(항목 고름, 캘린더에 추가)⇢ T06(여러 건) ─(추가)→ T05 "3건을 넣었어요"
```

- 탭 수 목표: 입력 1 + 시작 1 + 추가 1 + 확인 1 = **4탭**(항목 선택 해제 제외, 기본은 확인된 항목만 선택).

## 9. 알림·잠금 화면 설계

### 9.1 알림 종류별 문구

알림 제목·본문은 잠금 화면에 보여도 되는 수준으로 쓴다. 금액·대화 내용·전화번호·회원번호는 넣지 않는다(03 §6 흐름 6-1, NFR-SEC-09). 장소 이름은 넣는다(03 F-NOTI-03 예시 기준, 노출 여부는 DOD-5).

| 종류 | 제목 | 본문 | 행동 버튼 | iOS 중요도 | Android 채널·중요도 | 누르면 |
|---|---|---|---|---|---|---|
| 승인 요청(`decision`·`spend_cap`) | 확인이 필요해요 | 라 파스타 통화에서 정할 일이 있어요. 상대방이 기다리고 있어요. | Ph1: 없음(누르기만) / Ph2: [거절](앱 열지 않음) | Time Sensitive | "내 차례" · 높음 | T02 승인 카드 |
| 손 넘기기 필요 | 직접 해 주실 차례예요 | 구청 체육관 신청에서 본인 인증이 필요해요. | 없음 | Time Sensitive | "내 차례" · 높음 | T04 |
| 반복 회차 실행 확인(`run_confirm`, Ph2) | 관리사무소에 걸어도 될까요? | 매달 25일 관리비 확인 전화예요. | [이번만 건너뛰기] | Time Sensitive | "내 차례" · 높음 | 확인 카드 |
| 완료 | 라 파스타 예약됐어요 | 11월 28일(금) 오후 7시 · 결과를 확인해 주세요. | 없음 | Active | "진행·완료" · 기본 | T05 |
| 확인 못 함 | 라 파스타 결과를 확인해 주세요 | 예약 여부는 확인하지 못했어요. | 없음 | Active | "진행·완료" · 기본 | T05 |
| 실패 | 라 파스타에 연결하지 못했어요 | 직접 걸거나 다른 곳을 찾아볼 수 있어요. | 없음 | Active | "진행·완료" · 기본 | T05 실패 변형 |
| 반복 마감(L0) | ○○앱 출석 시간이에요 | 눌러서 바로 열고, 출석은 직접 해 주세요. | 없음 | Active | "마감 알림" · 기본 | 대상 앱(딥링크)·사이트 |
| 승인 만료(갱신) | 진행하지 않았어요 | 시간이 지나 라 파스타 예약금은 거절로 처리했어요. | 없음 | Passive(기존 알림 교체) | "내 차례" 알림을 교체 | T02 |
| 웹 작업 멈춤(Ph2) | 돌아오면 이어서 할게요 | 구청 체육관 신청을 잠시 멈췄어요. | 없음 | Active | "진행·완료" · 기본 | T03 |

규칙
- **상태가 바뀔 때만 보낸다.** 단계 하나하나(거는 중 → 신호 가는 중)는 알림이 아니라 잠금 화면 진행 표시로만 갱신한다(02 §1-5, 03 F-NOTI-04).
- **같은 내용을 겹쳐 보내지 않는다.** 진행 표시가 켜져 있으면 "통화 시작" 알림은 보내지 않는다(02 §4.1 Live Activities).
- **Time Sensitive는 내 차례에만**, 마케팅에 쓰지 않는다(03 F-NOTI-02, 02 §4.1).
- 승인 알림 Ph2 [승인] 버튼은 두지 않는다. 승인은 앱에서 카드를 보고 누른다(03 F-APPR-08, OD-6 권장안).

### 9.2 알림 권한을 거부한 경우

- 작업은 그대로 진행하고, 진행 카드·T02 상단에 "알림이 꺼져 있어요. 확인 요청을 놓치지 않게 화면을 켜 두세요 [설정 열기]"를 한 줄 둔다(§14 PR-2).
- SCR-M05 맨 위에 OS 알림 상태와 [설정 열기]를 둔다.

### 9.3 iOS Live Activity / Android Live Update 레이아웃

**표시 항목 우선순위**(좁은 공간일수록 위에서부터만 남긴다)

| 순위 | 항목 | 예 | 비고 |
|---|---|---|---|
| 1 | 단계 이름(내 차례면 "확인 필요") | 통화 중 / 확인 필요 | `live` 또는 `attention` 색 + 아이콘. 03 F-CALL-03의 단계 이름과 같은 말 |
| 2 | 대상 이름 | 라 파스타 | DOD-5 설정에 따라 "예약 전화"로 대체 가능 |
| 3 | 경과 시간 | 1:24 | 표 숫자. Android 상태 표시줄 칩과 펼친 카드의 시간 형식 일치(02 §4.2) |
| 4 | 단계 점 | ●─●─◉─○ | 4단계 고정(통화), 5단계(웹) |
| 5 | 행동 | [열기] | 하나만(03 F-NOTI-03). 끊기 버튼은 두지 않음(실수 방지, 가정) |
| 제외 | 금액, 대화 내용, 전화번호, 개인 정보 | — | NFR-SEC-09 |

```
[잠금 화면 / 펼친 알림]
┌──────────────────────────────────────┐
│ [전화] 라 파스타에 전화 중      1:24 │
│ 준비  거는 중  통화 중  결과 정리     │
│  ●──────●──────◉──────○              │
│                              [열기]  │
└──────────────────────────────────────┘
[내 차례]
┌──────────────────────────────────────┐
│ [손] 라 파스타 · 확인이 필요해요      │ attention
│ 상대방이 기다리고 있어요     [열기]  │
└──────────────────────────────────────┘
[다이내믹 아일랜드 축소] [전화]  통화 중 · 1:24
[최소]                   [전화] 또는 [손](내 차례)
[Android 상태 표시줄 칩]  [전화] 1:24
```

- **시작**: [이대로 시작] 직후(통화 `dialing`). **갱신**: 단계 바뀜, 내 차례 시작·끝. **종료**: 결과 정리가 끝나는 즉시 종료하고 완료 알림으로 넘긴다(02 §4.1 "끝나면 바로 종료"). 웹 작업은 앱이 앞에 있어야 진행되므로 `paused` 동안만 "멈춤" 표시를 두고 복귀하면 종료(가정).
- 사용자는 SCR-M05에서 진행 표시를 끌 수 있다(03 F-SET-02).
- 밝은·어두운 배경 두 벌, 아이콘은 단색.

## 10. 접근성·국제화

### 10.1 화면 읽기 순서와 실시간 영역

| 화면 | 읽기 순서 | 실시간 영역(언제, 무엇을, 몇 번) |
|---|---|---|
| H01 | 제목 → 입력칸 → 마이크 → 보내기 → 예시 칩 → 내 차례 → 진행 중 → 최근 장소 → 탭 바 | 받아쓰기 시작·끝 "듣고 있어요" / "받아 적었어요" 1회 |
| H02 | 보낸 부탁 → 결과 수 문장 → 후보 카드 → 다시 찾기 | 로딩 끝 "4곳을 찾았어요" 1회 |
| H04 | 제목 → 작업 종류 → 행들 → 접힌 줄 → 예상 시간 → 신뢰 줄 → [이대로 시작] | 검증 오류 1회 |
| T02 | 제목 → 부탁 → 타임라인 → 신뢰 줄 → 대화 → 승인 카드 → 끊기 | 단계 바뀜 1회(정중), 승인 카드 등장 "승인 요청: <질문>" 1회, 30·10초 각 1회, 응답 전송 결과 1회 |
| T03·T04 | 띠 → 기록 → 페이지 | 띠 문구 바뀜 1회(누가 조작하는지) |
| T05 | 결과 첫 줄 → 칸들 → 주 행동 → 보조 → 근거 | 결과 도착 시 첫 줄 1회 |

- 대화 기록은 실시간 영역으로 두지 않는다. 새 줄이 쌓이면 "새 대화 N줄" 버튼으로 알린다(매 줄 읽기 방지).
- 1초마다 바뀌는 숫자(남은 초, 경과 시간)는 읽기에서 뺀다(UX-001 REQ-012 확대).

### 10.2 누르는 영역

- 모든 누를 수 있는 요소 48×48 이상(Android 지침), iOS 44×44, 라벨 있음(UX-001 REQ-009). 대상 화면을 §4.9 목록으로 넓힌다.
- 주 버튼 높이 52, 하단 고정. 승인·거절은 같은 너비(UX-001 §7.3)로 실수 탭의 비대칭을 없앤다.
- 서로 다른 결과를 내는 버튼 사이 간격 `sm`(8) 이상.

### 10.3 큰 글자 2.0

- §4.9 규칙. 검사 화면: H01, H02, H04, T01, T02(승인 카드 포함), T04, T05, M01 — 360×640, 배율 2.0, 넘침 0, 주 버튼에 스크롤로 닿음.

### 10.4 움직임 줄이기

- 모든 토큰 움직임 0, 진행 점 정지, 스크롤은 `jumpTo`(UX-001 REQ-006). 카드 쌓임·접힘·띠 교차 페이드도 같은 도우미(`motionDuration`)로만 시간을 얻는다.
- 진행 점이 멈춘 상태에서도 "통화 중" 글자와 경과 시간으로 진행을 알 수 있어야 한다.

### 10.5 색에만 의존하지 않기

| 신호 | 색 | 색 외 신호 |
|---|---|---|
| 내 차례 | `attention` | 손 아이콘, "내 차례" 묶음 제목, 왼쪽 막대(모양), 남은 시간 글자 |
| AI 조작 중 | `live` | 띠 문구 "콜비가 입력하고 있어요", 테두리 두께 |
| 결과 4종 | 분위기 4색 | 아이콘 4종 + 첫 줄 문장 |
| 새 결과 | `primary` 점 | 접근성 라벨 "새 결과", 굵은 제목 |
| 비활성 | 흐림 | 이유 글자 |
| 걸 수 없는 번호 | `critical` 글자 | 느낌표 아이콘 + 문장 |

### 10.6 영어 확장 시 고려사항(03 OD-14: 수요 확인 후)

- 문구는 처음부터 키로 분리하고(현행 코드의 문자열 위치 정리는 구현 SPEC에서), 영어는 한국어보다 길어질 수 있으므로(가정: 30~40%) 버튼·칩 폭을 고정하지 않는다. 버튼 라벨 두 줄 허용.
- 해요체의 공손함은 영어에서 짧고 친근한 평서문으로 옮긴다("I'll let you know when it's done."). 직역하지 않고 원문 의미 기준으로 쓴다.
- 날짜·시각·금액은 `intl` 형식으로(한국어 "11월 28일(금) 오후 7시" ↔ 영어 "Fri, Nov 28, 7:00 PM"). 이름 순서(성·이름)와 존칭("김지은 님")은 로캘 규칙으로.
- 통화 언어(F-SET-04: 한국어·영어)와 화면 언어는 따로 고른다. 계획 카드 접힌 줄은 "영어로 걸어요"처럼 통화 언어를 항상 보인다.
- 아이콘 방향(뒤로 화살표)은 오른쪽에서 왼쪽으로 쓰는 언어를 지원할 때 반전한다(현재 범위 밖).

### 13.2 디자인 QA 체크리스트

- [ ] 화면마다 채운 주 버튼이 하나 이하이고 하단 고정 영역에 있다(DP-2).
- [ ] `attention` 색은 `waiting_user`·내 차례 요소에만, `critical`은 실패·끊기·삭제·탈퇴에만 쓰였다(D-1).
- [ ] 작업 종류 아이콘에 색이 없다.
- [ ] 모든 상태 표시가 아이콘 + 글자 + 색이다(DP-6).
- [ ] "처리 중", "로딩", "오류가 발생했습니다", "~하시겠습니까", "서버 주소" 같은 금지 문구가 없다(§2.2).
- [ ] 알림·잠금 화면 문구에 금액·전화번호·대화 내용이 없다(D-6).
- [ ] 확인 못 함 결과에 체크 아이콘·긍정 색이 없다(DP-5).
- [ ] AI 고지 한 줄이 H04·T02·T05·공유 문구에 있다(§2.4).
- [ ] 첫 실행 온보딩 동안 권한 요청이 없다(DP-7).
- [ ] 큰 글자 2.0, 다크 모드, 움직임 줄이기 세 조건을 각각 켠 상태로 주요 화면을 확인했다.
- [ ] 회색조 캡처에서도 상태가 구분된다.

```
오늘(H01) ─[가운데 비서 / 전화 대신하기]→ AI 비서(A01) ─[말하기 끝 ✓]→ 장소 선택(H02) ─→ 계획 확인(H04)
```

| 스택 | A01은 전체 화면 모달, H02·H04는 그 위 푸시. [비서에게 맡기기]가 성공하면 모달을 닫고 업무 탭을 선택한 상태로 T02를 연다(탭 전환 + 푸시, §6.3) |

### 17.2 SCR-H01 오늘

- **목적**: 앱을 열면 비서가 먼저 오늘 챙길 일을 알려 준다(Proactive).
- **세로 순서**: 워드마크 줄(로고, 알림 버튼) → 날짜·인사("좋은 아침이에요, 지은 님." / "오늘도 제가 함께할게요.") → 브리핑 카드(CMP-37) → 비서에게 부탁하기(2×2 바로가기, CMP-38) → 확인이 필요해요(있을 때만) → 진행 중(있을 때만) → 오늘의 일정(P1).
- **데이터**
  - 확인이 필요해요 = 업무 탭 "승인 요청"과 같은 계산(§3.5 묶음 함수). 개수 배지는 Warning.
  - 진행 중 = 진행 중 묶음의 첫 1~2건, 인디고 진행 막대와 단계 이름.
  - 브리핑(Phase 1, DOD-12): "오늘 중요한 일이 N개 있어요." N = 승인 대기 + 진행 중 + 오늘 일정(연동 전에는 0). 설명 줄은 승인 대기 → 진행 중 → 어제 끝낸 일 순으로 한 문장씩 규칙으로 만든다. 문장 생성(F-HOME-01)은 Phase 2.
  - 바로가기: 전화 대신하기 → A01 / 일정 관리(P1) / 메일 확인(P1) / 정보 찾아보기 → A01(검색 의도). P1 항목은 1차 출시에서 숨기지 않고 "곧 쓸 수 있어요"로 비활성(03 §4.15의 "쓸 수 없는 것도 숨기지 않는다" 준용).
- **빈 상태**: 작업이 하나도 없으면 브리핑 카드 문구가 "오늘은 맡긴 일이 없어요. 가운데 버튼으로 부탁해 보세요."로 바뀌고, 확인·진행 묶음은 숨긴다.
- **접근성**: 브리핑 카드 전체가 하나의 버튼("오늘의 브리핑, 중요한 일 3개, 브리핑 확인하기"). Orb는 장식(`aria-hidden`).

### 17.4 SCR-A01 AI 비서

- **목적**: 어디서든 말이나 글로 부탁한다(Voice-first).
- **진입**: 가운데 비서 버튼, 오늘의 [전화 대신하기]·[정보 찾아보기], 결과의 [조건 바꿔 다시](말한 문장 채움).
- **구성**(몰입형 다크): 제목 "AI 비서" + 닫기 → Orb 상태 칩 → Orb(168) → "무엇을 도와드릴까요?" / "말씀해 주시면 제가 대신 처리할게요." → 실시간 받아쓰기 문장 → 하단 "이렇게 부탁해 보세요" 예시 칩 2개(F-REQ-03) → 하단 조작 줄 [글로 입력] · [말하기 끝 ✓](주 버튼, 인디고 원) · [그만하기].
- **상태**: 대기(처음 열면, 마이크 권한 전이면 CMP-23 사전 안내) / 듣는 중 / 처리 중("부탁을 살펴보는 중이에요") / 응답 중(되묻기 한 문장을 소리와 글로, F-REQ-06) / 인식 실패("잘 못 들었어요. 다시 말하거나 글로 적어 주세요").
- **글로 입력**: 누르면 아래에 입력칸이 열리고 Orb는 작아진다(64). 보내기는 [말하기 끝]과 같은 흐름.
- **접근성**: 마이크가 켜져 있는 동안 "듣고 있어요" 칩이 늘 보인다(02 §3.3). 받아쓰기 문장은 실시간 영역이 아니라 마지막에 한 번 읽는다.
- **관련**: F-ASST-01·02, F-REQ-01·02·03·06, SPEC-ASSIST-001.

### 17.5 SCR-T01 업무

- **구성**: 제목 "나의 업무" / "비서가 처리하는 모든 업무를 확인하세요." → 개수 세 칸(진행 중 · 승인 대기 · 완료, 완료는 오늘 기준) → 승인 요청(승인 카드 축약형: 칩 · 제목 · 설명 · [자세히]→T02 · [승인]) → 진행 중(행: 상대 · 단계 · 상태 칩) → 반복 → "끝난 업무는 기록에서 볼 수 있어요 ›".
- **묶음 규칙**: 11 §3.5 개정. 끝남 묶음이 빠진 것 외에는 원래 규칙(§7.8)과 같다.
- **승인 요청 카드에서 바로 [승인]**: 내용(금액·조건)이 카드에 다 보일 때만 허용하고, 금액 상한 칩이 필요한 승인(`spend_cap`)은 [자세히]만 둔다(02 §5 P13 "내용 확인 뒤 승인").

### 17.6 SCR-T02 업무 실행 · SCR-T08 통화 중

**SCR-T02 업무 실행**(라이트)

- 머리: 뒤로 · [● 통화 보기](통화 중일 때만) → 제목(업무 이름, 예: "저녁 식당 예약하기") · "AI 비서 · 전화 대행 · 라 파스타" · 상태 칩.
- 내 승인 단계일 때: 승인 카드(CMP-15)를 타임라인 위에 둔다. 남은 시간, [거절]/[승인].
- 업무 진행 상황: CMP-34. 단계 계산은 11 §3.6.
- 아래 신뢰 줄: "승인이 필요한 일은 확인 없이 실행하지 않아요."

**SCR-T08 통화 중**(몰입형 다크)

- 머리: 뒤로(T02) · [통화 끊기](Error 계열, 확인 시트) → Orb(64, 응답 중) · "통화 중 · 1:24" · 상대 이름 · 부탁 요약.
- 본문: 실시간 자막(CMP-13). 화자 이름(콜비 / 상대)을 말풍선 위에 둔다. 아래 "실시간 자막 · 통화는 글로 기록돼요".
- 승인이 오면: 밝은 바텀 시트로 승인 카드. 금액 상한 칩·빠른 답 칩·[거절]/[승인].
- 끝나면: 결과(T05)로 바뀐다.

### 17.7 SCR-R01 기록

- **구성**: 제목 "기록" → 검색칸("장소, 통화 내용, 요약 검색", F-INBOX-06은 Ph2라 1차는 숨김 또는 장소 이름 검색만, 가정) → 거르기 칩(전체 · 통화 · 요약 · 실패) → 날짜 묶음("오늘 · 11월 26일") → 기록 카드(제목 · 결과 칩 · 한 줄 요약 · 통화 시간 · 결정 기록 수).
- **누르면**: 결과(T05).
- **새 결과 점**: 아직 보지 않은 결과는 카드 제목 옆 인디고 점(F-INBOX-03).
- **삭제**: 카드 길게 누르기 → "이 기록을 지울까요? 지우면 되돌릴 수 없어요."(F-INBOX-04).

### 17.9 자동 검사 추가(§13.3에 더함)

- 업무 탭 배지 수 = 오늘 "확인이 필요해요" 개수 = 업무 "승인 요청" 개수(같은 함수).
- 상태 칩 5종이 모두 아이콘·글자·색을 갖는지.
- 몰입형 다크 화면(A01·T08) 글자 대비 4.5:1(다크 값 기준).
- Orb가 있는 화면에서 움직임 줄이기를 켜면 Orb 애니메이션이 멈추는지.
- 다섯 칸 탭 바가 글자 배율 2.0·360 폭에서 넘치지 않는지.
